# notebook-source-pack — 노트북에서 모으고, 파일로 뽑아, 클로드에서 쓴다

출처: 오빠두엑셀 「제미나이 노트북이 완전히 달라졌습니다」(KPrqrQ1QL2M · 2026-11-19) 의 3단계(모으기 → 채우고 거르기 → 뽑기)를
우리 도구(`nlm` CLI · `yt-dlp`)로 옮긴 것. 영상의 북마클릿 2종은 쓰지 않는다(코드 비공개 · 로그인된 페이지에서 남의 스크립트 실행).

## 언제 쓰나 / 안 쓰나
- 쓴다: 공개 자료(유튜브 영상 · 웹 페이지 · 공개 보고서) 수십~수백 개를 근거로 보고서·대본·분석을 만들 때. 출처를 사람이 넣고 빼며 관리해야 할 때.
- 안 쓴다(멈춘다):
  - **개인정보·교적·상담·재정·내부 문서**(교회·회사·학교 무엇이든) — 구글 서버로 올라간다. 이런 자료는 노트북에 올리지 않고 내 컴퓨터 안에서만 다룬다.
  - 개인 문서·비공개 자료 — 사용자가 이 길을 직접 지시한 경우만.
  - 자료 10개 이하로 끝나는 조사 — 그냥 WebSearch/WebFetch 나 deep-research 가 빠르다.

## 미리 알아 둘 숫자 (공식 · 2026-11-20 확인 · 쓰기 전에 다시 본다)
| 요금제 | 노트북당 소스 | 노트북 수 | 근거 |
|---|---|---|---|
| 무료 | 50 | 100 | support.google.com/notebooklm/answer/16213268 · …/gemininotebook/answer/16215270 |
| Plus | 100 | 200 | 16213268 표(열 순서로 읽음 · 확신도 중) |
| Pro | 300 | 500 | 16213268 · Google One 도움말 14534406 |
| Ultra | 500 / 600 | 500 | 16213268 표(열 순서로 읽음 · 확신도 중) |
- 소스 1개 = 최대 50만 단어 또는 200MB. 유튜브는 **공개 + 자막 있는 영상만** · 자막 글만 들어간다 · 올린 지 72시간 안 된 영상은 안 들어갈 수 있다(16215270).
- 질문 한도는 「계산량 기준」으로 숫자 공개 없음 · Deep Research 는 한도 넘으면 일부만 가져온다(16215270).
- **소스 원문 일괄 내보내기는 공식 기능이 없다** → 우리는 `nlm source content`(비공식 CLI)로 뽑는다.

## 순서
0. **준비**: `nlm login` 상태 확인(nlm-skill 「Authentication」). `nlm` 은 팩 각성 점검(`preflight --fix`)이 설치한다. 명령 정본 스킬 nlm-skill 이 좌석에 없으면 `nlm skill install claude-code` 를 한 번 돌린다(그 도구가 자기 판에 맞는 스킬을 깐다). 쓸 계정의 요금제 = 위 표에서 노트북당 상한 N.
1. **모으기 — 유튜브**(북마클릿 「유튜브 링크 일괄 복사」 대신):
   ```bash
   yt-dlp --flat-playlist --print "%(id)s|%(duration)s|%(view_count)s|%(title)s" "ytsearch80:<검색어>" > list.txt
   ```
   - **list.txt 는 지우지 말고 보관한다** — nlm 0.10.0 은 유튜브 소스의 주소(url)를 비워 주므로, 뽑을 때 `--url-map list.txt` 로 제목→주소를 채운다(11-20 실가동 실측).
   - 쇼츠·짧은 영상 빼기 = `duration` 이 180초 미만인 줄 제외 · 신뢰도 = 조회수 큰 순으로 정렬 → 위에서 N개.
   - 채널 하나의 인기 영상: 채널 `/videos` 주소를 같은 명령으로 받은 뒤 조회수로 정렬한다(목록은 최신순으로 오므로 인기순 정렬은 우리 쪽에서 한다 · 영상이 많은 채널은 전체를 받아야 정렬이 맞다).
   - 받은 목록의 조회수는 반올림 값이고 `NA`(라이브·회원 전용 등)가 섞인다 · 제목이 영어 번역으로 올 수 있다 → 판단은 ID·길이·조회수로 하고 제목은 참고만(2026-11-20 실측).
   - 넣기: `nlm source add <노트북> --youtube <주소1> --youtube <주소2> … --wait` (20개 안팎씩 나눠서).
2. **모으기 — 웹**: `nlm research start "<주제>" --notebook-id <노트북>`(빠른 · 약 30초) 또는 `--mode deep`(깊은 · 약 5분) → `nlm research status` → `nlm research import <노트북> <작업ID>`(필요한 번호만 `--indices`).
3. **채우기**: 노트북에 빠진 것을 묻고, 답에 나온 검색어로 2를 다시 돌린다.
   ```bash
   nlm notebook query <노트북> "<주제>로 리서치할 때 지금 소스에서 누락되거나 부족한 내용이 뭐야? 더 찾을 검색어 3개로 답해."
   ```
4. **거르기**: 먼저 기계로, 그다음 모델로.
   - 기계(정본): 5단계 스크립트가 처리 실패(status 3)·처리 중·글자 수 `--min-chars` 미만을 **묶음에서 뺀다**(노트북에서 지우지 않는다 · 제외 목록 = manifest.json).
   - 글자 수는 넘지만 본문이 없는 페이지(쿠키 동의문·로그인 벽)는 빼지 않고 「의심」으로 표시한다(manifest `suspect_boilerplate` · 실행 끝 출력) → 직접 열어 보고 필요하면 `--min-chars` 를 올리거나 그 소스를 지운 뒤 다시 뽑는다. 선례: 소스 154건짜리 노트북에서 4건이 쿠키 동의문뿐이었다.
   - 모델(보조): `nlm notebook query <노트북> "이 소스 중에서 불필요하거나 비어 있는(회사 소개·메뉴·국가 코드만 있는) 소스가 뭔지 제목으로 알려 줘."` → 답은 **후보**일 뿐 · `nlm source content <ID>` 로 글을 직접 보고 판단한다.
   - 노트북에서 실제로 지우기(`nlm source delete`)는 하지 않아도 된다. 묶음에서 빼는 것으로 충분하다.
5. **뽑기**(북마클릿 「노트북 소스 추출」 대신):
   ```bash
   python3 <이 스킬 폴더>/scripts/pack_sources.py <노트북1> [<노트북2> …] --out <새 폴더> [--min-chars 500] [--part-chars 400000] [--url-map list.txt]
   ```
   - 결과: `pack.md`(전체 · 크면 `pack-01.md`… 로 나뉨) · `sources/NNN.md`(소스별) · `manifest.json`(목록·글자 수·sha256·제외 이유).
   - 소스 상한을 넘는 조사 = 노트북을 여러 개 만들어 1~4를 반복하고, 5에서 노트북 ID 를 모두 넘긴다(하나의 묶음).
6. **쓰기**: Claude 세션에 `pack.md`(또는 나뉜 파일) 경로를 주고 일을 시킨다. 근거를 댈 때는 각 소스 머리의 「출처」 줄을 인용한다.
   - 클로드 앱에 끌어다 놓을 때는 나뉜 파일 단위로 올린다.

## 주의할 점
- `nlm` 은 **비공식 도구**다(구글 내부 호출을 흉내 냄 · MIT · github.com/jacob-bd/gemini-notebook-mcp-cli · 확인한 판 0.10.0). 구글 화면이 바뀌면 깨질 수 있다 → 실패하면 `nlm --version` 과 nlm-skill troubleshooting 부터.
- 「소스 무제한」은 노트북 상한이 사라진다는 뜻이 아니다. 노트북을 나눠 담고 파일로 합치는 것이며, 병목은 **받는 AI 의 한도**로 옮겨 간다. 참고 = 15분 한국어 영상 자막 ≈ 5,800자(KPrqrQ1QL2M 실측 · 시각 표기 제외) → 영상 50개 ≈ 29만 자.
- 묶음 파일에는 남의 저작물 원문이 그대로 들어 있다 → **내부 조사용** · 묶음 자체를 바깥에 공개·배포하지 않는다.
- 출력 폴더는 비어 있어야 한다(덮어쓰기 방지). 중간에 실패하면 새 폴더 이름으로 다시 돌린다.
- 유튜브 자막이 없는 영상은 노트북에 안 들어간다(실패 소스로 남음 → 4단계에서 자동 제외).

## 확인하는 방법
- `manifest.json` 의 `kept` 개수 + `excluded` 개수 = `nlm source list <노트북> --json` 의 소스 수 합과 같아야 한다.
- `pack.md` 머리의 「전체 N개」와 `sources/` 파일 수가 같아야 한다.
- 빈 소스 후보로 빠진 것 3개를 골라 `nlm source content` 로 직접 열어 정말 비었는지 본다(기준값 `--min-chars` 조정용).

## 원 설명 (목록 상주 설명 축소 전 원문 · 1.1.16 cysr-1116-asset-skills-1120)

조사 자료를 노트북(NotebookLM · 제미나이 노트북)에 모으고 → 모자란 것 채우고 → 빈·실패 소스 거르고 → 모든 소스 원문을 파일 묶음(pack)으로 뽑아 Claude 세션에서 쓰는 절차. 노트북 소스 상한(무료 50 · Pro 300)을 넘는 양은 노트북을 나눠 담고 묶음으로 합친다. 「노트북 소스 파일로 뽑아」·「유튜브 영상 수십 개 모아 분석」·「인기 채널 영상 공통점 분석」·「출처를 내가 고르는 리서치」·「노트북 자료를 클로드로 넘겨」 요청 때 발동. 노트북 조작 명령 자체는 nlm-skill 이 정본이고, 이 스킬은 그 위의 작업 순서와 거르기·뽑기 도구만 담는다.
