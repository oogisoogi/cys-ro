# portrait-cutout 참고 — 단계마다의 이유와 알려진 한계

이 방법은 고화질이 아닌 인물 사진을 웹 첫 화면(히어로)에 전경으로 얹으려고 여러 판을 거쳐 다듬은 것이다.
아래 순서는 「바꾸어 보았더니 품질이 내려갔던」 실측 순서다 — 순서를 바꾸거나 단계를 빼기 전에 이 표를 먼저 본다.

## 사진 처리 단계와 이유

| 단계 | 하는 일 | 왜 이렇게 하나 |
|---|---|---|
| 1 가림 | 맥 Vision **전경(foreground)** 가림 | 사람(person) 가림은 해상도가 낮아 테두리가 번진다. 전경 가림은 원해상도에 가깝다 |
| 2 단단하게 | 가림을 원해상도에서 128 문턱으로 자르고 3px 깎기 | 첫 판에서 가림을 흐리게(가우시안 1.2px) 했더니 테두리가 뿌옇게 보여 선명한 느낌이 사라졌다. 깎기는 배경 테(흰 벽·책장)를 잘라 낸다 |
| 3 가장자리 색 정리 | 안쪽 7px 의 색을 바깥 띠로 번지게 하고 원래 색과 반반 섞기 | 밝은 배경이 가장자리에 비쳐 생기는 옅은 후광을 없앤다 |
| 4 미세 선명 | 약한 언샤프 마스크 | 원본이 흐릴 때 윤곽만 살짝 세운다 |
| 5 자르기·크기 | 높이 맞춰 축소 · 머리 위 여백 · 좌우는 실제 화소 경계 | 투명 여백이 들쭉날쭉하면 쪽에 얹을 때 위치가 어긋난다 |
| 6 밝은 테 채우기 | 지정 구역(`--fringe-box`)에서 경계 근처 밝은 화소를 같은 줄 안쪽 옷 결로 덮기 | 어깨·옷 둘레에 남는 흰 테를 옷 색으로 메운다 |
| 7 입체감 | 국부 대비(반경 40 · 24%) · 대비 1.04 · 채도 1.05 · 밝은 곳 눌림(200 위를 0.6배) · 윤곽 안쪽 음영(가장자리 0.8 → 안쪽 1.0) | 입체감은 그림자를 붙여서가 아니라 사진 자체에서 만든다. 밝은 곳 눌림은 이마가 하얗게 날아가는 것을 막는다 |
| 8 저장 | WebP q92 알파(또는 32비트 PNG) | 256색 PNG 로 줄이면 피부에 계단 무늬가 생긴다 |

- 결과 확인은 언제나 **어두운 바탕 위 확대 3곳**(어깨 · 귀 · 머리카락)으로 한다.
- 귀·머리 옆의 흰 테는 `--fringe-box` 로 덮으면 피부 색을 기준 삼아 오작동할 수 있다. 그 구역은 「경계 6px 안 · 밝기 205 초과 · 안쪽으로 찾아 덮기」를 따로 손으로 해야 한다(아직 자동화 안 됨).

## 쪽(웹)에 얹을 때
- 그림자는 **아래로 떨어뜨리지 말고 둘레에 고르게** 준다 — 목표는 「아래 그림자」가 아니라 「전체가 앞으로 튀어나와 보이는 것」.
  ```css
  filter: drop-shadow(0 0 14px rgba(10,0,22,.6)) drop-shadow(0 0 1px rgba(255,255,255,.16));
  ```
  첫째 = 둘레 고른 그늘, 둘째 = 1px 테두리 빛.
- 투명 칸 뒤에 은은한 **뒤 조명**을 깔면 투명 부분으로 비쳐 인물이 떠 보인다(값은 바탕 색에 맞춰 조정 — 아래는 짙은 보라 바탕 기준 예):
  ```css
  background: radial-gradient(ellipse 52% 46% at 50% 34%, rgba(255,228,250,.24), rgba(255,228,250,.08) 55%, transparent 78%);
  ```
- 비율: 인물 높이는 영역 높이의 80% 대 중반 · 머리 위 여백 약 16% · 인물 아래는 다음 줄(카드 등) 뒤로 이어지게. 위아래를 꽉 채우면 답답해 보인다.

## AI 생성 그림(초록 바탕) 오리기
무료 그림 생성 도구는 투명 바탕을 잘 못 만든다. 방송 합성(크로마키)처럼 **처음부터 순초록 바탕으로 그리게 하고 코드로 초록을 뺀다**.

- **그릴 때**: 프롬프트 끝에 「그림자 없이, 완전히 평평하고 고른 순초록(#00FF00) 단색 바탕 위에 따로 놓인 모습」을 붙인다. 영어 예(우리 문장): `on a solid, evenly lit pure chroma green (#00FF00) backdrop, no shadows, no gradients, subject fully separated from the background`. 옷·소품에는 초록을 쓰지 말라고 함께 적는다(초록 옷은 같이 지워진다).
- **뺄 때**: 「초록이면 투명」 단순 문턱은 쓰지 않는다. 가장자리의 반쯤 초록인 화소가 남아 초록 실선이 된다.
  - 알파 = 초록이 얼마나 우세한가: `255 − (g − max(r,b)) × 255 / 180` 을 0~255 로 자른다.
  - 넘침 억제: `g ← min(g, max(r,b))` — 가장자리에 비친 초록 기운을 걷어 낸다.
  - `portrait_cutout.py --green` 이 이 두 줄을 한다.
- **흰 테두리 스티커로 가려지지 않는다**: 단순 문턱 결과에 흰 테두리를 둘러도 테두리 안쪽에 초록 실선이 그대로 보였다(합성 시험).
- 확인 = 어두운 바탕 위 확대(사진과 같은 규칙).
- 시험 근거(모두 합성 그림 · 실제 AI 생성 그림은 아직 시험 안 함): 안티앨리어싱 가장자리의 합성 실루엣에서 단순 문턱은 초록 실선 화소 427개(이전 시험) / 378개(이 스킬 시험 ②)가 남았고, 우세도 알파 + 넘침 억제는 0개였다.
- 착상 출처(우리 말 요약 · 원문 미동봉): 오빠두엑셀 영상 https://www.youtube.com/watch?v=KUcAEisnvic — 무료 그림 생성에서 초록 바탕으로 그리게 한 뒤 코드로 빼는 흐름. 넘침 억제 규칙과 시험은 우리 것.

## 알려진 한계(다음에 다듬을 것)
1. 귀·머리 옆 흰 테 자동 처리(피부를 잘못 덮지 않는 규칙이 아직 없다).
2. 머리카락 잔털 보존 — 3px 깎기로 잔털이 사라져 가까이 보면 머리선이 매끈하다.
3. 뒤 조명 색을 바탕 색에서 자동 계산 — 지금은 바탕마다 손으로 맞춘다.
4. 원본이 이미 고화질이면 7단계(입체감)를 약하게 — 과보정 방지. 원본 선명도를 재서 세기를 자동으로 정하는 것이 다음 과제.

  https://developer.apple.com/documentation/vision/vngenerateforegroundinstancemaskrequest
  https://developer.apple.com/documentation/vision/vngeneratepersoninstancemaskrequest
