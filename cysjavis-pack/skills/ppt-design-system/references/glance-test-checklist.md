# 점검표 — 3초 테스트(첫 화면 · 슬라이드 · 보고서 한 장)

> 출처: Duarte 글랜스 테스트(「청중은 요점을 3초 이내에」 · duarte.com/resources/slide-glance-test/ · 원문은 옮기지 않고 기준만) · Anthropic 공식 `frontend-design` 스킬의 「대담함은 한 곳에만」 · unslop(CC-BY-4.0 · 「고칠 양을 먼저 정한다」 방법만) · 우리 영상 보고 덱(`video-report-deck`)의 「강조 하나」.
> 영상·문서의 문장은 가져오지 않았다(구조와 기준만).

## 0. 한 줄 요지
**처음 보는 사람의 시선 순서를 번호로 적어 보고, 핵심 하나가 1번이 될 때까지 주변을 낮춘 뒤, 다시 적어 확인한다.** 더하지 않는다. 지우지 않는다. 낮춘다.

## 1. 언제 쓰나
| 산출 | 쓴다 | 쓰지 않는다 |
|---|---|---|
| 사이트 첫 화면 · 새 페이지 | 내보내기 전 1회(PC 1280 + 폰 390 따로 — 모바일은 축소판이 아니라 따로 설계) | — |
| 슬라이드(PPT · 영상 보고 덱 · 강의 화면) | 장마다(특히 숫자 카드·표가 있는 장) | 표지·간지 |
| 문서형 보고서(PDF·HTML) | 첫 장 · 한 장 요약 · 장 제목 | 부록·원자료 표 |
| 고정 양식(기관 공식 서식 등) · 원문 그대로 규칙이 걸린 것 | — | 쓰지 않는다(양식이 정본) |
| 사용자가 정한 배치·구성 | 사실만 적어 보인다 | 바꾸지 않는다 |

## 2. 순서
### ① 목적과 핵심을 먼저 적는다
- **목적 한 줄**: 이 화면/장을 본 사람이 무엇을 알거나 해야 하나(예: 「처음 온 사람이 모임 시각과 오는 길을 안다」).
- **핵심 문장 하나**: 그 목적을 한 문장으로(예: 「모임은 토요일 오전 11시입니다」). 사용자가 준 문장이 있으면 그 문장을 쓴다.
- 이 둘을 못 적으면 디자인 문제가 아니라 **내용 문제**다 → 디자인을 손대기 전에 사용자에게 묻는다.

### ② 진단 — 3초 시선 순서를 번호로 적는다
- 실제로 렌더한 화면을 본다(브라우저 100% 배율 스크린샷 · 슬라이드는 PNG 로 렌더 · 축소 캡처·짐작 금지).
- 처음 보는 사람의 눈이 가는 순서대로 요소를 1·2·3… 적는다. 각 요소에 **크기·굵기·색 실값**(CSS 값 · pt)을 붙인다.
- 핵심 문장이 몇 번인지, 그보다 앞선 요소가 무엇인지(= 시선을 다투는 것) 적는다.
- **고칠 양을 먼저 정한다**: 걸리는 곳이 많으면 전체 · 조금이면 그 자리만(원래 색·글꼴 유지) · 없으면 「괜찮다」고 적고 정확한 값이 붙은 제안 2~3개만, 적용은 동의 뒤. 좋은 화면을 달라 보이려고 바꾸지 않는다.

### ③ 수정 — 주변을 낮춘다
측정 가능한 기준(아래 §3)을 맞추는 쪽으로만 고친다. 배치 자체는 새로 짜도 된다.

### ④ 재진단 — 다시 번호로 적는다
- 핵심이 1번이 됐는지, 필수 정보가 빠지지 않았는지(§3 ⑥) 대조표로 남긴다.
- 고치기 전/후 스크린샷 두 장을 산출물에 붙인다(가능하면 만든 사람이 아닌 다른 눈이 ②④를 한다).

## 3. 측정 기준(합격선)
| # | 기준 | 재는 법 |
|---|---|---|
| ① | **핵심 하나가 시선 순서 1번** | ②④ 번호 목록 |
| ② | 핵심 요소가 다음으로 큰 요소보다 **뚜렷이 크다**(시작값 = 2배 · 실측 근거가 쌓이면 고친다) | 실값 비교(px · pt) |
| ③ | **같은 크기·같은 굵기로 경쟁하는 요소가 없다**(제목 = 브랜드명 · 숫자 카드 전부 같은 크기 등) | 실값 표 |
| ④ | **강조색은 한 곳**(주 단추 또는 핵심 숫자) · 나머지는 회색·보조 | 색 실값 개수 |
| ⑤ | **정보가 아닌 장식 0**: 이모지 단추 · 배지 · 그라데이션 씻김 · 똑같은 그림자 · 3D 막대 · 모델 기본 색(녹색 베이스 등) | 눈 + 검색(`gradient` · `box-shadow` · 이모지) |
| ⑥ | **필수 정보는 지우지 않고 낮춘다 — 나쁜 숫자도 남긴다** | 전/후 정보 항목 대조표(빠진 것 0) |
| ⑦ | **새 요소·새 문구를 더하지 않는다**(문구 변경은 사용자가 시켰을 때만) | 전/후 글자 비교 |
| ⑧ | 제목은 가능하면 **결론 문장**(「매출 현황」 → 「매출이 38% 늘었다」) · 질문형 제목이면 답을 같은 장에 크게 | 장 제목 목록 |
| ⑨ | 글자 바닥은 그대로: 읽는 글 20px(웹) · 슬라이드 본문 24pt — 「낮춘다」는 바닥 아래로 내린다는 뜻이 아니다 | font-size 18px 미만 0 |
| ⑩ | 상태가 바뀌면 첫 화면 문구도 바뀐다(마감 · 공지 종료 · 판 교체) | 상태값과 첫 화면 문구 대조 |

## 4. 말로 시킬 때(지시문 · 산출 마지막에 붙여 쓴다)
```
이 <화면/장>의 목적은 <목적 한 줄>이고, 핵심 문장은 「<핵심 문장>」이다.
1. 진단: 처음 보는 사람이 3초 볼 때 눈이 가는 순서대로 요소를 번호로 적고, 각 요소의 크기·굵기·색 실값을 붙여라. 핵심과 시선을 다투는 요소를 짚어라.
2. 수정: 핵심이 1번이 되도록 주변을 낮춰라. 배치는 새로 짜도 된다.
   - 핵심은 다음으로 큰 요소보다 뚜렷이 크게(시작값 2배). 같은 크기·같은 굵기로 맞선 요소를 남기지 마라.
   - 강조색은 한 곳에만. 정보가 아닌 장식(이모지·배지·그라데이션·그림자)은 빼라.
   - 필수 정보는 지우지 말고 낮추기만 하라. 나쁜 숫자도 남겨라.
   - 새 요소·새 문구를 더하지 마라. 글자 바닥(웹 20px · 슬라이드 24pt) 아래로 내리지 마라.
   - 짧은 문구: 제목·단추·라벨 끝에 마침표를 찍지 마라(여러 문장 단락만) · 인사 제목 대신 그 화면의 맥락(쪽 이름·기간) · 확인 안 되는 숫자 문구(「1만 명 사용 중」)는 묻고, 근거가 없으면 지워라.
3. 재진단: 고친 뒤 다시 시선 순서를 번호로 적고, 핵심이 1번인지·빠진 정보가 없는지 대조표로 보여라. 전/후 스크린샷을 붙여라.
```

## 5. 주의
- **3초 테스트는 「더 예쁘게」가 아니다** — 「잘 읽힌다」를 재는 것이다. 문구·표현 손질을 품질 작업으로 세지 않는다.
- **효과는 아직 잰 적 없다** — 합격선(특히 ② 2배)은 시연과 원리에서 온 시작값이다. 전/후를 사람 눈으로 대조한 기록이 쌓이면 그때 값을 고친다.
- 새 도구를 들이지 않는다 — 이 점검표는 말로 시키는 지시문에 붙는 칸 목록이다.
