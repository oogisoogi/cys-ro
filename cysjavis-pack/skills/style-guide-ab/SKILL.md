# style-guide-ab — 두 모양 중 고르게 해서 만드는 맞춤 가이드

근거 = 오빠두엑셀 「AI 요금제 바꾸기 전에, 이것부터 설정하세요 | 맞춤형 AI 가이드 제대로 쓰는 법」(youtu.be/J46UyJDT5kw · 11:49 · 2026-11-11) — 방법만 가져왔고 문항 원문은 옮기지 않았다.

## 왜 이 방법인가
- 「더 깔끔하게」「더 전문적으로」 같은 말은 고칠 곳을 가리키지 않아 결과가 잘 안 바뀐다(영상 3:00~3:40). 사람은 **설명은 못 해도 둘 중 고르기는 잘한다.**
- 그래서 설명을 요구하지 않고, 같은 내용을 한 가지만 다르게 만든 두 모양을 보여 주고 고르게 한다. 고른 것이 곧 규칙이 된다.
- 처음 만든 가이드는 초안이다. 쓰면서 고친다(영상 5:20~5:40).

## 언제 쓰나 / 안 쓰나
- 쓴다: 같은 종류 결과물(보고·메일·회의록·슬라이드·표·차트·화면)을 사용자가 두 번 넘게 고쳐 달라고 할 때 · 새 종류의 결과물을 처음 맡을 때 · 다른 사람(교역자·부서 담당자)에게 자비스를 처음 붙여 줄 때.
- 안 쓴다: 한 번 쓰고 말 결과물 · 사용자가 이미 정확히 짚어 말한 것(「이 글꼴 쓰지 마」 = 그 자리에서 규칙 한 줄로 적으면 끝) · 사용자 규칙 문서에 이미 있는 축(다시 묻지 않는다).

## 순서

### 1. 영역 하나를 고른다
틀 = 기본 정보 · 답변 방식 · 보고서·기획서 · 메일·메신저 · 회의록·요약 · 슬라이드 · 표 서식 · 차트 · 화면 디자인(영상 도구의 9묶음과 같은 갈래). 그 밖(주보·기안서·설교 원고·공지 문안 등)도 같은 방법으로 된다. **한 번에 한 영역만.** 지금 가장 자주 고치는 영역부터.

### 2. 가진 것을 먼저 읽는다 (묻는 수 줄이기)
- 사용자가 이미 쓰는 문서·슬라이드·스크린샷·지난 결과물이 있으면 먼저 받는다. 사진 한 장이어도 된다(영상 6:20~6:50).
- 거기서 **이미 정해진 축**(글꼴·색·제목 방식·번호 매김·문단 길이·존댓말 수준 등)을 읽어 표로 적는다 → 그 축은 묻지 않고 「이렇게 읽었습니다」로 확인만.
- 사용자 지침·기억에 이미 적힌 규칙도 같은 표에 넣는다. 이미 답한 것을 다시 묻지 않는다.

### 3. 갈리는 축만 뽑는다
- 영역마다 축 8~10개가 보통이다(예: 길이 · 결론을 먼저/나중 · 강조 방식 · 번호/글머리 · 표/문장 · 말투 · 숫자 표기 · 여백 · 색 쓰는 곳 · 마무리 방식).
- 2번에서 정해진 축을 빼고, 남은 축마다 문항 1개(답이 흔들리는 축만 1개 더). **합계 10~15문항**을 넘기지 않는다.

### 4. 문항을 만든다
- **사용자의 실제 일감**으로 만든다(지난 보고·이번 주 공지 등). 빈 예시 글 금지.
- 두 모양은 **한 축만** 다르다. 내용·길이·나머지 모양은 같게.
- A·B 자리는 문항마다 섞는다(늘 A 가 「기본」이면 A 로 쏠린다).
- 한 문항이 한 화면에 들어오게 짧게.

### 5. 보여 주고 답을 받는다
- 글(말투·길이·구조) = 대화창에 「A」「B」 두 덩이.
- 모양(슬라이드·표·차트·화면) = 한 장에 좌우로 나란히 그려 **화면에 바로 띄운다**(파일 경로만 주지 않는다).
- 답 = `1`(A) · `2`(B) · `3`(둘 다 괜찮음) · `0`(둘 다 별로) · 건너뛰기. 문항 3~5개를 한 번에 내고 「1 2 3 1」처럼 한 줄로 받는다.
- 안내 한 줄: 「오래 고민하지 마시고 눈에 먼저 들어오는 쪽으로. 초안이라 쓰면서 고칩니다.」
- `0` 이 나온 축은 무엇이 싫은지 한 마디만 묻거나, 2번 레퍼런스 쪽 모양으로 한 번 더 낸다. 두 번 `0` 이면 「미정」으로 남긴다.

### 6. 가이드를 쓴다
- 규칙 한 줄 = **언제 + 이렇게 한다 (+ 하지 않는 것)**. 「깔끔하게」 같은 형용사로 쓰지 않는다.
- 줄마다 출처 표시: 〔고름〕 = 사용자가 고른 것(확정) · 〔읽음〕 = 레퍼런스에서 읽은 것(확인 받음) · 〔기본〕 = 둘 다 괜찮음(기본값일 뿐 · 상황에 따라 바꿔도 됨) · 〔미정〕.
- 맨 위 세 줄 고정: ① 이 가이드가 다루는 결과물 ② 대화에서 따로 말한 것이 이 가이드보다 우선 ③ 가이드 내용을 결과물에 옮겨 적지 않는다.
- 파일 = `<영역>-가이드.md`(만든 날 · 근거 문항 수 · 고친 기록 절).

### 7. 나눠서 등록한다
- **평소 행동과 내 정보**(누구인지 · 어디서 일하는지 · 답하는 말투) = 지침. **특정 작업 방식**(보고서·슬라이드·차트 만드는 법) = 작업별 가이드/스킬(영상 7:30~8:20).
- 사용자의 지침 문서(CLAUDE.md 등)에 넣는 것은 **넣을 줄을 보여 주고 승인 받은 뒤**에만. 작업별 가이드는 파일로 두고 그 작업 때 읽는다.
- 웹 서비스 사용자: 지침 = 설정의 지침 칸에 붙여 넣기 · 가이드 = 스킬 올리기. 로컬(Claude Code·데스크톱) = 파일을 주고 「이 파일 기준으로 동작하게 설정해 줘」(영상 11:10~11:30).

### 8. 정말 달라졌는지 한 번 확인한다
같은 요청 1건을 가이드 없이 / 가이드로 만들어 5번 방식으로 나란히 보인다. 사용자가 가이드 쪽을 고르면 등록 끝. 아니면 어긋난 축을 찾아 3번으로.

### 9. 쓰면서 다듬는다
- 사용자가 결과물을 고쳐 달라고 하면, 고친 뒤 **그 자리에서 가이드 한 줄을 고치거나 더한다**(고친 날 · 까닭).
- 같은 지적이 두 번 나오면 규칙이 빠졌거나 문장이 흐린 것 — 문장을 「언제 + 이렇게」로 다시 쓴다.
- 〔기본〕·〔미정〕 줄은 실제 결과물에서 반응이 나올 때 확정한다. 문항을 다시 돌리지 않는다.

## 걸리는 시간(영상 수치 · 우리 실측 아님)
영상 도구는 영역 하나에 문항 40~50개 · 약 8분(화자) · 전부 만들면 30분~1시간. 이 스킬은 레퍼런스를 먼저 읽어 10~15문항으로 줄인다 — 우리 쪽 걸린 시간은 첫 사용 때 재서 여기에 적는다(미측정).

## 하지 않는 것
- 오빠두엑셀 도구의 문항 원문을 가져다 쓰지 않는다(그쪽 저작물 · 회원 로그인 뒤 내려받는 서비스). 가져온 것은 방법과 틀(영역 갈래 · 축 수)뿐이고, 문항은 사용자 일감으로 새로 만든다.
- 사용자를 그 사이트에 보내 가입시키는 것을 기본으로 삼지 않는다(원하면 주소만 안내: oppadu.com/tools/ai-guide).
- 문항 수를 늘려 정밀해 보이게 하지 않는다. 사용자의 시간이 비용이다.

## 원작과의 관계
| | 영상(오빠두엑셀 도구) | 이 스킬 |
|---|---|---|
| 문항 | 미리 만든 은행(영역당 40~50) | 그 사람 일감으로 그때 만든 10~15 |
| 레퍼런스 | 초안을 만든 뒤 다듬을 때 | 문항 앞에서 먼저 읽어 묻는 수를 줄임 |
| 답 | 1 · 2 · 3(둘 다 괜찮음) · 넘기기 | 같음 + 둘 다 별로(0)는 한 번 더 |
| 산출 | 지침 + 스킬 파일 묶음 | 같음(규칙마다 출처 표시 추가) |
| 확인 | 넣기 전후가 다르다는 화자 시연 | 같은 요청 전후 1건을 사용자가 직접 고름 |

## 원 설명 (목록 상주 설명 축소 전 원문 · 1.1.16 cysr-1116-asset-skills-1120)

사용자가 「깔끔하게 해 줘」 한마디만 해도 그 사람·그 조직 방식대로 결과물이 나오게, 같은 내용을 두 모양(A/B)으로 보여 주고 고르게 해서 맞춤 가이드(지침 + 작업별 가이드)를 만드는 스킬 — 우리 판 「내 AI 가이드 만들기」(오빠두엑셀 J46UyJDT5kw). 영역 고르기 → 가진 레퍼런스에서 이미 정해진 것 읽기 → 갈리는 축만 A/B 문항(사용자 실제 일감으로) → 1·2·둘 다 괜찮음·둘 다 별로 → 규칙 한 줄씩 가이드 → 지침/스킬로 나눠 등록 → 적용 전후 1건 비교 → 쓰면서 다듬기. "내 스타일대로 / 우리 교회(회사) 서식대로 / 맞춤 가이드 만들어 / 스타일 가이드 / AB 테스트로 가이드 / 결과물이 매번 마음에 안 들어 / 깔끔하게가 안 통해" 요청 때, 또는 같은 종류 결과물을 두 번 넘게 고쳐 달라는 말이 나올 때 발동. 화면의 AI 티 걷어내기는 frontend-design·3초 점검표, PPT 서식 추출은 ppt-design-system 을 쓴다.
