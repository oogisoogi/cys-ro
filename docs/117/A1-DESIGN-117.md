## 0. 공통 원칙(세 파일 모두)
1. **정확히 0바이트만** 복구 대상이다. 공백만 · BOM만 · 해석 불가 · 권한 오류 = 지금처럼 **무변경 거부**(v1.1.6 「모든 오류 = 빈 상태」 회귀 금지). 단 F1 키 파일은 원래 계약이 「비어 있지 않은 바이트 = 키」 라 공백도 키다(그대로 둔다).
2. 0바이트 판정과 복구 쓰기는 **같은 프로세스 간 잠금 안**에서 **실제로 다시 읽어** 한다(크기만 보고 판정 금지 — 읽기 권한 오류인 빈 파일을 덮는다).
3. **잠금을 못 잡으면 쓰지 않는다**(무잠금 폴백 없음).
4. 게시는 **완성된 임시 파일 → 원자 게시**. 보장 범위 = 부분 파일이 경로에 보이지 않음(원자 가시성). 전원 장애 뒤 영속성은 임시 파일 fsync 까지이며 폴더 fsync 는 하지 않는다(기존 쓰기 관례와 같음).
5. 복구는 알린다: 무엇을 새로 만들었는지 · 무엇은 되살아나지 않는지(옛 승인 · 옛 부서).

## 1. F1 `~/.cys/.approval-secret` — `approval.rs signing_secret_at`
**잠금** = `lock_key_exclusive(p)` = `<p>.cys-lock` 을 std `File::lock()`(Rust 1.89+ 안정 · CI 전 레인 `dtolnay/rust-toolchain@stable` · 유닉스 = flock · 윈 = LockFileEx)으로. 유닉스에서는 `pack::acquire_settings_lock` 과 같은 flock 이다. 이 키 파일은 cysd 만 만진다(파이썬 동료 없음) → 이종 잠금 문제 없음 · `acquire_settings_lock` 의 「윈 = None」 한계를 물려받지 않는다.

**절차(모든 생성·복구가 이 하나)**
```
① 잠금 없이 읽기: 비어 있지 않음 → 그 키 · 읽기 오류 → None(무변경)
② 부재 또는 0바이트 → 폴더 준비(실패 = None) → 잠금(실패 = None · 아무것도 만들지 않음)
③ 잠금 안 재판독: 비어 있지 않음 → 그 키 · 오류 → None
④ 난수 32B → 임시 키(create_new · 0600 실패 = 실패 · write_all · sync_all)
⑤ 게시: 0바이트 = rename(원자 교체) · 부재 = hard_link(비참여 writer 가 먼저 쓴 키 보존 · AlreadyExists → ⑥)
        · 그 밖 hard_link 오류(하드링크 불가 FS 등) = 잠금 안 rename
⑥ 경로 재판독: == 내 키 → 내 키 · 비어 있지 않은 다른 키 → 그 키(비참여 writer 선게시) · 빈 값·오류 → None
   (게시·확인 실패 = None · 「세션 한정 키」 반환 없음 · 임시 파일은 언제나 지움 · 잠금은 ⑥ 끝까지)
```
- **없앤 것**: `publish_secret_exclusive`(create_new 로 빈 파일을 먼저 만들고 나중에 쓰는 길 = 0바이트 생성 원인 · 신판끼리 「반환 키 ≠ 경로 키」 경합 원인 · codex 2R Q3-1). 잠금 실패 폴백 전부.
- **⑥의 위치**: 검증 보조다 — 참여자끼리의 배제는 잠금이 한다(재판독이 이미 난 덮어쓰기를 되돌리지는 못한다 · codex 2R Q3-3).
- **영향(좁힌 서술)**: 읽을 수 있는 기존 키·유효한 환경변수 키가 없고 **새로 게시해야 하는데 못 하는 경우**만 `approval.sign` = `secret_unavailable`(종전 = 「성공」 이지만 호출마다 다른 키라 쓸모없는 서명).
- **옛 승인 재서명 금지**: `approval.check` 는 **현재 키로 검증된 바로 그 기록(위치)** 만 갱신·재서명한다 — 종전 `find(id)` 는 같은 id 의 앞선 옛 기록을 재서명할 수 있었다(선재 · codex 2R Q3-8 반례) → `best_match` 가 고른 기록의 위치(`ptr::eq`)로 갱신(handlers.rs).
- **구판 데몬(정정)**: v1.1.6 은 부재·빈 파일을 읽은 뒤 `fs::write` 로 **직접** 쓴다(잠금·하드링크 없음) — 구판 A 가 판독 뒤 멈춘 사이 신판 B 가 게시·반환하고 A 가 쓰면 B 의 키가 덮인다. ⇒ **갱신 뒤 구판 데몬이 모두 종료된 것을 확인한 다음에만** 이 복구가 안전하다(⑦ 게이트에서 갱신 절차의 데몬 재기동을 대조 · 미확인이면 절단 전 【확인요청】 에 명시).
- 공격자 절단(단일 UID): 키 재생성 유발 = 옛 승인 무효화(재승인 필요) · 권한 경계 우회 아님(codex 1R ⑵(c)).

## 2. F2 `~/.cys/approvals.json` — `load_records_at`
- 잠금 = 기존 `lock_records()`(읽기·변경·저장 전 구간 · 호출부 handlers.rs 2곳 그대로).
- 규칙: 읽은 내용이 **정확히 0바이트** → 빈 목록. 선두 BOM 하나를 벗긴 뒤 해석 — 실패 = Err(BOM 파일 전체를 빈 목록으로 접지 않음). 공백만·BOM만 = Err.
- 저장 = 기존 `save_records`. 이전 승인은 복원되지 않는다(0바이트엔 복원할 것이 없다) → 재승인.
- **무잠금 한계(선재 · 넓어지지 않음)**: 윈 `lock_records()` = None · 유닉스도 잠금 파일 열기·획득 실패 = None(무잠금 진행). 두 데몬이 잠금 없이 동시에 0바이트를 읽고 저장하면 한쪽 새 기록이 빠질 수 있다(기존 lost-update 와 같은 창).
- 읽기 전용 호출부(schedule.rs:933) = 0바이트 → 빈 목록(승인 없음 = 막는 쪽).

## 3. F3 `~/.cys/depts.json` — `cys-dept`
- **reg_init**: 빠른 길 `[ -s "$REG" ] && return 0`(셸만 · 쓰지 않음) → 부재·0바이트만 파이썬: 쓰기 동사와 같은 잠금(`$REG.lock`) · **잠금 실패 = 예외 = 쓰지 않음**(윈 msvcrt 실패를 삼키지 않음) → 잠금 안에서 **실제로 읽어** `FileNotFoundError` 또는 읽기 성공한 `b""` 일 때만 `{"depts":{}}` 를 tmp(pid 이름 — 호출마다 새 파이썬) + fsync + `os.replace`. 읽기 권한 오류 = 알리고 무동작(→ 뒤의 엄격 판독이 12). 실패는 stderr 알림 뒤 넘긴다(판정은 엄격 판독).
- **알림 구분**: 부재에서 처음 만들 때 = 무음. **0바이트 초기화 때만**: 「…빈 목록으로 다시 만들었습니다 — 목록 초기화이지 복구가 아닙니다. 전에 있던 부서 폴더와 실행 중인 부서는 목록에 돌아오지 않습니다」.
- **판독 규칙 9곳**: `reg_read_py` + 잠금 블록 8곳(reg_upsert·reg_remove·reg_fence_close·reg_set_meta·reg_set_field·allocate·create·reap) = 원시 바이트가 비었을 때만 `{"depts":{}}` · 그 밖은 `utf-8-sig` 해석(실패 = 12). 잠금 블록 8곳은 0바이트를 받으면 같은 뜻의 알림(「빈 목록으로 다룹니다 — 목록 초기화이지 복구가 아닙니다 …」 · 빠른 길 통과 뒤 외부 절단 경로 · codex 2R Q3-7).
- **범위 밖(명시)**: ⑴ `reg_get_field`(선택 필드 조회 · 판독 오류 = 빈 출력 계약 · 0바이트 = 빈 출력으로 결과 동일) ⑵ `down-sock` 역인덱스 `json.load(open(p))`(BOM 미흡수 선재 · DBG-C3 §5 「차단 아님」 · 초기화 실패로 0바이트가 남은 경우에만 예외) ⑶ 기존 쓰기 블록들의 윈 msvcrt 잠금 실패 무시(`except OSError: pass` · v1.1.6 동일 선재 — 신설 reg_init 만 고침).
- **cys-dept 밖 판독자는 바꾸지 않는다(v1.1.6 대조)**: `javis_dept_request.registry()`(v1.1.6 `:258-266` = `json.load` ValueError → RegistryUnreadable) · GUI `list_depts`(v1.1.6 `main.rs:4871-4880` = `serde_json::from_str("")` Err) — **둘 다 v1.1.6 에서도 0바이트 = 판독 실패** ⇒ 회귀 아님. v1.1.6 자가 치유는 cys-dept 쓰기 경로에서만 났다. 두 판독자는 **reg_init 초기화가 성공한 뒤** 유효 JSON 을 읽는다(실패하면 v1.1.6 과 같이 판독 실패 유지). 넓히면 틱의 「부서 없음」 판정(편성 원장 이동)이 앞당겨진다 — 넓히지 않는다.
