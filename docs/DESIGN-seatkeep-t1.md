## 1. 임대 키 — 같은 대화는 언제나 한 키

- **키 = `sha256("v1\0" + 정규화(session_id))`** · 정규화 = 앞뒤 공백 제거 + ASCII 소문자. **경로는 키에 넣지 않는다.**
- 근거: 초안은 (계정 폴더 정본 경로, 세션 저장소, session id) 였다. 경로를 키에 넣으면 별칭·심볼릭 링크·대소문자(맥 APFS 기본 = 대소문자 무시)·`..`·하드 링크 때문에 **같은 대화가 두 키로 갈라질 길**이 생긴다 — 갈라지면 두 작성자를 못 막는다(되돌릴 수 없는 쪽). 반대로 경로를 빼면 생길 수 있는 오류는 「다른 대화를 같은 키로 묶음」 하나뿐인데, 그것은 ⓐ 세션 id 는 UUID 라 충돌 확률이 사실상 0 ⓑ 프로필 폴더를 통째로 복사한 경우(같은 id 의 jsonl 이 두 곳) 뿐이고, 그 결과는 「두 번째 복원이 이유를 표시하고 안 뜸」 = **안전한 쪽 오류**다. 소문자화도 같은 논리다(대소문자만 다른 두 id 를 하나로 묶는 쪽으로만 틀린다).
- 계정 폴더는 임대 **속성**으로만 적는다(표시·감사용): `cfg_canon`(canonicalize 결과) · `cfg_devino`(장치·inode). 판정에는 쓰지 않는다.
- **저장 위치 = 사용자 단위 한 곳**: 유닉스 `$HOME/.local/state/cys/session-leases/` · 윈 `%LOCALAPPDATA%\cys\session-leases\`. 지금 claim 은 `daemon_state_dir(소켓)` 아래라(`25686`) 소켓이 다른 데몬(윈 부서 파이프 = 슬러그별 폴더 · `src/lib.rs:608`)끼리는 같은 대화를 서로 못 본다 → 임대는 소켓과 무관하게 둔다. 시험은 임시 HOME 으로 격리된다(별도 노브 없음). 【D4 조건】 폴더 0700 · 파일 0600 · 만들 때 심볼릭 링크를 따라가지 않는다(`symlink_metadata` 로 종류 = 폴더/일반 파일 · 소유자 = 나 확인 · 파일은 `O_NOFOLLOW`) · 하나라도 어긋나면 U4.

## 2. 보유자 신원 — pid 단독 금지

- 임대 파일 1개 = JSON 1줄: `{v, key_id, fence, state, writer, restorer, daemon_gen, surface_id, cfg_canon, cfg_devino, at}`. 교체는 `<폴더>/.lock` 배타 잠금(지금 `restore_claims_lock` 와 같은 방식 · `25524`) 안에서 임시 파일 + rename.
- **신원 = (pid, 출생 초, 출생 마이크로초)** — 이미 있는 leaf 모듈 `src/process_observation.rs` 의 `Identity`(맥 `proc_pidinfo(PROC_PIDTBSDINFO)` 의 `pbi_start_tvsec/usec` `:200-234` · 리눅스 · 윈 핸들)를 그대로 쓴다. 맥 헤더 `sys/proc_info.h:80` `pbi_start_tvsec` 확인.
- `state` 3값: **launching**(복원기가 잡고 기동 중 · `restorer` 신원만) → **held**(작성자 프로세스 확인 · `writer` 신원) / **unknown**(기동 결과 불명 · ⑪ — 풀지 않는다).
- `writer` 찾기 = 기동 뒤 그 좌석 루트의 자손 중 **argv 에 그 session id 원소가 있는 에이전트 프로세스**(process_observation `Invocation.argv`). 못 찾으면 `launching` 으로 남기되 `surface_id`·`daemon_gen` 을 적어 다음 판정이 데몬에 물을 수 있게 한다.
- `fence` = 그 키에서 임대를 잡을 때마다 +1(잠금 안에서 이전 값을 읽고 올림). 해제·갱신은 **내 fence 일 때만** 한다(늦게 깨어난 옛 복원기가 새 임대를 지우거나 덮지 못함).

## 6. 600초 claim 의 축소 · 옛 판과의 공존

- 노브 켬(기본): 판정 정본 = 임대. 옛 claim 파일은 **계속 만든다** — ⚠「옛 판이 보고 비킨다」는 처음 서술은 틀렸다(독립 검증 F4 실측): 옛 판(1.1.14)은 claim 을 보면 **비키지 않고 `--resume` 을 끈 새 대화로 기동**한다(「저장 대화를 이미 다른 좌석이 잇는 중 — 이어 붙이지 않고 새 대화로 기동」) · 남의 claim 은 **60초 안 것만** 동률로 존중(옛 판 복원기가 지금 기동 중일 수 있는 틈 = cmux 의 claim TTL 60초와 같은 목적 · 【문서】 2026-11-02 cmux 2-4) · 그보다 오래된 남의 claim 은 판정에 쓰지 않는다(① 의 원인 제거).
- 60초 동률 확인 자리 = 공통 관문 `lease_gate` — 복원 입구 셋(`cys restore` · `launch-agent --resume-saved` · `node-recover`) 모두(master#388727f0 M3 = B · codex 1R M3).
- **남는 창(지원 범위 밖 · 숨기지 않음 · 독립 검증 F4 실측으로 고쳐 씀)**: 같은 대화를 **임대를 모르는 옛 판 `cys restore`**(업데이트 창의 옛 앱 사이드카)와 새 판 복원이 **거의 같은 순간**에 잇는 경우.
  - 실제 결과(독립 검증 V7·V7B · 새 판 시작 뒤 0/0/30/80ms 에 옛 판): **작성자 둘 0/12** · 그러나 **옛 판이 새 대화로 띄워 그 역할의 저장 대화를 바꿔 끼운 회차 5/12**(rc = 새 0·옛 0, 또는 새 92·옛 0) = **대화 바꿔 끼움(조용한 소실 · 11-01 은폐와 같은 모양)**. 대조: 새+새 0/8 · 옛+옛 6/8 → **회귀는 아니다**(옛 판끼리가 더 나빴다).
  - 처음 서술 「이론상 작성자 둘」은 실제 위험 이름이 아니었다 — 실제 위험 = 업데이트 창에서 한 역할의 대화가 새 대화로 바뀌는 것(이전 대화 파일은 남지만 그 역할은 새 대화로 이어감).
  - 창 길이 근거 = 임대 판정 구간(조용할 때 중앙 22ms · 부하 때 40~100ms · HANDOFF F) + 데몬 조회 + 옛 판의 claim→기동 시간.

- 노브 끔: 종전 경로 그대로(임대 파일 읽지도 쓰지도 않음 · 남아도 무해).

## 8. 바깥 표준과 함정 → 우리 처리 (1줄씩)

- **임대 만료(lease timeout)** — 보유자가 멈춘 사이(GC·SIGSTOP·지연) 만료돼 둘이 동시에 쥔다 · 시계가 뛰면 일찍/늦게 풀린다(Kleppmann 2016) → **우리 임대는 시간으로 풀리지 않는다.** 보유자가 「죽음 확인」일 때만 인수한다. 대가 = 판정 불가면 막힘(그래서 U1~U8 을 rc·사유로 드러낸다).
- **fencing token** — 저장소가 토큰을 검사해야 효과가 있다(Kleppmann: 「storage server must … reject any write carrying a lower token」). Claude 의 jsonl 쓰기는 우리 토큰을 검사하지 않는다 → **fence 로 막을 수 있는 것은 임대 파일 자체의 갱신·해제뿐**임을 인정하고, 작성자 하나는 「띄우기 전 판정」으로만 보장한다(이미 떠 있는 둘을 떼어 놓는 장치는 아님 · 그 경우는 rc 92 로 드러남).
- **파일 잠금(flock)** — 권고(advisory) 잠금이고 열린 파일 설명자 단위라 같은 프로세스의 두 번째 open 이 스스로 막히며, fork·dup 으로 공유되고 NFS 에서 흉내만 낸다(man flock(2)) → 잠금은 판정 순서용으로만 · 소유는 파일 내용(fence·신원)으로 · 이미 있는 「잠금 쥔 채 다시 잡지 않는다」 규칙(`25512` 주석) 유지 · 상태 폴더는 로컬 디스크 전제.
- **pid 파일** — pid 재사용으로 남의 프로세스를 보유자로 착각(processkit·laburnum 문서: pid 와 시작 시각을 짝지어 비교) → (pid, 출생 초·마이크로초) 짝 · 판독이 프로세스 종료와 경합하면 판정 불가(U1)로.

- 예상 = 60~75분(follow 함수·조상 거슬러 오르기·시험 · S1/S2 에 얹음) → 조건대로 **범위에 넣어 진행**(90분 이하 · CLI 등록 경로 leaf 호출 · 데몬 수정 0).

## 13. 【조건 ③】 거짓 막힘 측정 (합격 기준 추가)

- **정상 조건 복원 100회 → rc 93 = 0회.** U6(argv 판독 실패)는 1초 안에서 재시도(최대 3회 · 간격 250ms) 뒤에만 판정 불가로 친다 · U1·U2 도 같은 재시도.
- **복원 1건당 늘어난 시간**: 노브 켬/끔 각 100회의 임대 판정 구간(잠금 → 판정 → 획득 · 프로세스 훑기 포함)을 단조 시계로 재서 중앙·p95·최대 보고.
- rc 93 표시 줄 끝에 **사람이 풀 수 있는 다음 행동 1줄**을 사유별로 고정한다 — 예: `probe:EPERM` → 「`ps -p <pid> -o pid,lstart,command` 로 그 프로세스를 확인하고, 이 대화를 쓰는 중이 아니면 그 프로세스를 끈 뒤 다시 `cys restore`」 · `daemon:unreachable` → 「`cys status` 로 데몬을 확인한 뒤 다시」 · `lease:malformed` → 「`<임대 파일 경로>` 를 열어 보고 지운 뒤 다시(지우면 그 대화의 보유 기록이 사라진다)」.
- **남는 거짓 막힘(안전 쪽 · 92) — 낡은 argv**: `--resume A` 로 뜬 작성자가 /clear 로 B 로 옮긴 뒤에도 프로세스 argv 에는 A 가 남는다 → 그 작성자가 살아 있는 동안 A 의 복원은 92(사유 줄에 그 pid) 로 거절된다.
  고치지 않는 이유(codex 1R M4 → 2R blocking): 「다른 대화 임대의 작성자」 기록만으로는 그 작성자가 좌석 안 /resume 으로 A 에 **돌아왔는데 등록(SessionStart)이 아직 안 닿은** 순간과 가를 수 없다 — 제외하면 작성자 둘의 창이 생긴다. 이 티켓의 불변식(작성자 하나)이 복원 편의보다 앞선다.
  사람이 풀 길: 사유 줄의 pid 가 A 를 쓰지 않는 것을 확인하면 그 좌석을 닫거나(작성자 종료) 기다린다 · 정상 조건(작성자만 죽은 재복원 · 두 입구 동시)에는 이 거짓 막힘이 생기지 않는다(S4 rc 93·92 계수).
- **결과 불명(⑪) 임대의 좌석 = 엄격 판정(codex 4R)**: 큐에 남은 기동 명령이 아직 닿을 수 있으므로 「빈 셸(seat=empty · agent_alive≠true)」 관측은 죽음이 아니다 → `daemon:seat-empty-unconfirmed`(93 · 다음 행동 = 그 좌석을 보고 아니면 닫기). 죽음 = 좌석 소멸 · exited · 그 데몬 죽음 확인만. **작성자 없이 남은 기동 중(launching) 임대도 같은 엄격 판정(codex 5R)** — 복원기가 기동 명령을 친 뒤 결과를 적기 전에 급사하면 셸이 에이전트를 exec 하기 전 빈 셸·argv 증거 없음 상태가 생긴다. 정상 흐름은 마무리(hold)·등록(follow)이 작성자를 적으므로 작성자 없는 임대는 이미 비정상 · R1 재복원(작성자 확인 = held → 작성자 죽음 = 인수)은 영향 없음(e2e R1 rc93 0).
- **기동 명령을 보낸 뒤 = 결과 불명(codex 6R)**: `boot_agent_on_surface` 가 기동 명령 직전에 그 좌석을 적는다(`lease_note_launch` · 접미 부착 여부 포함). 그 뒤의 **일반** 오류(set_meta·read_text 등)도 「안 떴다」가 아니다 → node-recover = 임대 유지(keep_unknown) · 좌석 재연결 = fresh 폴백 0 · rc 91 · 새 좌석 기동 = 좌석을 못 닫으면 rc 91(임대 유지 · 닫았으면 좌석과 함께 작성자도 내려가므로 되돌림).
- **멱등 키에 대화 ID · 재반환 좌석 3갈래(r4 A · codex 3R #1·#2·#3 · 설계 = `docs/DESIGN-seatkeep-t1-r4.md`)**: `launch-agent` 멱등 키 = 종전 `la-{역할}-{에이전트}-{cwd 해시}` + 잇는 기동이면 꼬리 `-s{정규화 대화 id}`(`launch_idem_key` · 데몬엔 불투명 문자열 = 규약 변화 0 · 옛 데몬 호환). 그래서 120초 안 같은 역할·폴더라도 **다른 대화의 좌석을 재반환받지 않는다**(같은 대화의 재시도만 같은 좌석). 그래도 재반환 + 에이전트 살아 있음으로 기동을 건너뛰면 `reused_seat_verdict`: 그 좌석 자손 argv 나 등록 대화가 이 대화 = 잇는 중(rc 0 · 임대 = 그 좌석) · 등록 대화가 다른 대화 = rc 93 + 임대 되돌림 · 등록 없음·topology 판독 실패 = 판정 불가 rc 93 + 임대 유지(「다른 대화」로 단정하지 않는다) · 그 좌석은 남의 것일 수 있어 닫지 않고 stdout 좌석 줄도 내지 않는다. rc 93 의 좌석 규칙 = 「이 대화를 쓰고 있을 수 있는 좌석」(재반환 판정 불가)만 좌석을 돌려줘 호출자가 임대를 유지 · 그 밖 93 = 좌석 없음 = 되돌림 · 복원은 93 을 commit·ok 로 세지 않는다(요약 꼬리 「생존 판정 불가 N」).
  - **새 동작 1(릴리스 노트 후보 문장)**: 「같은 역할이 다른 대화로 이미 떠 있을 때 저장된 대화를 이어 켜면, 이제 그 창을 다시 쓰지 않고 새 창에서 저장된 대화를 잇습니다(종전에는 2분 안이면 그 창을 그대로 두고 저장된 대화는 열리지 않았습니다).」 — 비특권 역할은 데몬 latest-wins 로 역할 이름이 새 창으로 옮고 · `worker` 는 `worker-N`. 120초가 지난 뒤의 종전 동작과 같다.
- **잇지 않는 기동은 저장 대화의 임대를 쥐지 않는다(codex 6R)**: `cys restore --no-resume` = 임대를 잡지 않음 · 접미 없이(저장 jsonl 없음 등) 새 대화로 뜬 기동 = 마무리에서 되돌림. (5R 판단의 전제 「작성자 없이 남은 임대는 비정상」을 이 두 길이 깨고 있었다 — 고친 뒤 남는 작성자 없는 임대 = 마무리에서 작성자를 못 찾은 기동(실제 Claude 빈도 미실측 · 독립 검증 좌석 몫) · 결과 불명 · 복원기 급사.) 작성 중(held)인데 작성자 없는 기록 = `lease:malformed:held-without-writer`.
- **데몬 응답 계약(codex 3R)**: 임대 판정은 데몬 응답의 판정 필드를 형식까지 본다 — `system.topology` live 원소 = `surface_id` 수 · `seat` ∈ {occupied, empty, unknown} · `session_id` 키 상존(문자열 또는 null) / `surface.list` 원소 = `surface_id` 수 · `exited` bool · `seat` 세 낱말 · `agent_alive` bool 또는 null. 어긋나면 `daemon:malformed-*`(93). ⚠`session_id` 키는 cysd **1.1.9** 부터 상존 — 그보다 옛 데몬과 새 `cys` 의 조합에서는 모든 임대 복원이 93 이 된다(안전 쪽 · 노브 `CYS_SESSION_LEASE=off` 로 종전). 우리 릴리스는 1.1.14 기준이라 실제 조합은 없다.
- 판정 불가 사유 추가(codex 1R·2R 고침): `scan:enumerate`(프로세스 열거 실패) · `daemon:malformed-topology`·`daemon:malformed-surface-list`(원소 형식) · `daemon:gen-unknown`(세대 없는 임대의 좌석) · `daemon:other-gen-alive`(살아 있는 다른 데몬의 좌석 — 다음 행동 = 그 데몬 소켓으로 확인) · `lease:mine-stale`(이 실행이 잡은 임대가 그 사이 넘어감) · `lease:lock:timeout`(잠금 5초) · `lease:lock:kind:*`(임대·잠금 파일 종류·소유자) · `lease:claim:*`(옛 claim 판독 오류).
