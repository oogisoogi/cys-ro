## 1. 묶음 정보를 어디에 두나 · 복원 길
- 화면 상태 = 앱(`cys-layout-v2` 안 `ws.tabs = {order:[묶음키], active, zoom?}`) — 묶음 키는 **문자열(폴더 이름)** 이라 재부팅으로 좌석 번호가 새로 발급돼도(`wsreconcile.ts:7-10` · `state.rs` next_id) 그대로 맞는다.
- 좌석 → 묶음 = ① 사람이 옮긴 기록(앱 `cys-layout-v2.seatGroup`, 열쇠 = `소켓+역할`, 역할 없으면 `소켓+cwd`) ② 없으면 자동 규칙(§5). 번호를 열쇠로 쓰지 않는다.
- ★트리는 하나만 둔다: `ws.tree` = 지금처럼 「전 좌석」 트리(입양·유령 퇴거·부서 간 이동·저장 경로 무변경). 탭 화면은 **보기 전용 파생 트리** = 고정 기둥(master·cso) + 고른 묶음 좌석으로 `autoArrange` 를 다시 돌려 만든다. 탭 안에서 경계선을 끌면 `ws.tabs.ratio[묶음키]` 에만 기록.
- 데몬은 수정하지 않는다(부트 체인·phoenix 복원·topology.json 무접촉 → 닻 치명 4군 해당 없음). 예외 1건 = §5 「말로 옮기기」용 메모리 필드.

## 3. 숨은 탭 좌석의 터미널 크기
- 지금도 다른 부서의 좌석은 DOM 에서 떼어지고 PTY 는 마지막 크기를 유지한다(`fitPane` 가드 `main.ts:4768-4770` · 출력은 계속 xterm 에 쓰임 `:4738`). 숨은 탭도 **똑같은 길**(떼어 두기)을 쓴다 → read-screen·send 는 데몬 쪽 화면이라 숨김과 무관.
- 몰림 방지: `fitPane` 에 「마지막으로 보낸 열·행」 기억 → 같으면 `resize_surface` 를 보내지 않는다(`:4773`) · 탭 전환은 `render()` 의 rAF 1회 안에서만 맞춤(`:5436`). 20회 왕복 시 크기 변경은 「실제로 달라진 좌석 × 1회」로 줄어든다.
- 숨은 채 새로 붙은 좌석은 120×35(`:7264`)로 두었다가 처음 보일 때 1회 맞춤.

## 4. 한 묶음에 좌석이 많을 때 (#C-12) · 고정 기둥 폭 (2b-3 · 박사님 11-11 13:1x · 지시서 2026-11-11-cysr-pillar-width-rule)
- **고정 기둥(master·cso) 폭 — 탭 화면에서만**: `기둥 열 수 = clamp(64, ⌊배치 영역 열 수 × 36%⌋, 96)` (grouptabs.pillarCols·tabPillarShare · 정수 백분율). 배치 영역 열 수 = 배치 영역 px ÷ 실측 글자 칸(글자 크기·글꼴을 따라감 · px 고정값 없음). 기둥 px = 열 × 글자 칸 + 칸 여백(실측).
  · 같은 배치 영역 폭·글자 크기·글꼴이면 한 번 잰 몫을 그대로 쓴다(매번 재면 75↔77열로 흔들려 탭 왕복마다 크기를 다시 보냈다) · 창 크기·글자 크기·글꼴이 바뀌면 탭 화면만 다시 그린다.
  · 사람이 경계를 끌어 정한 폭(leftAuto 표지 없음)이 있으면 그 폭이 이긴다(기존 「탭 간 폭 유지」 · 새 저장 열쇠 없음) · 눌렀다 떼기만 하면 아무것도 쓰지 않는다.
  · 오른쪽이 좁아져도 기둥을 64열 밑으로 줄이지 않는다 — 몫 상한은 기존 끌기 상한(0.85)뿐(새 최소 창 폭 동작 없음).
  · 묶음 탭 노브 끔(또는 묶음 1개) = 1.1.14 그대로(창의 25% · 노트북이면 90열 · 상한 50% = formation.defaultLeftShare).

## 5. 자동 배정 · 말로 옮기기
- 자동: master·cso = 고정 기둥(탭 무관 ②). 그 밖 = 좌석 **생성 폴더**(`state.rs:2281` cwd · live_cwd 아님 = 일하다 cd 해도 탭이 안 흔들림)의 마지막 이름(`/`·`\` 둘 다 자름). 같은 이름 = 같은 묶음. 묶음 순서 = 처음 나타난 순.
- 말로 옮기기: 사용자 → master 에게 말 → master 가 **새 명령** `cys seat-group --surface <번호> <묶음이름>` 실행 → 데몬 RPC `surface.set_group`(메모리 필드 1개 + 이벤트 `surface.group.changed` · 호출자 = master 역할 또는 사람 CLI만) → 앱이 받아 `seatGroup` 에 영속. 기존 명령에 얹을 곳 없음(set-status 는 자기 좌석만 `handlers.rs:10897` · surface.rename 은 제목 = 모델 조각과 충돌 `panetitle.rs:24`).
- 앱이 꺼져 있을 때 옮긴 값: 앱 시작 때 `surface.list` 의 `group` 을 읽어 `seatGroup` 에 영속 → 남는 한계 = 「데몬 재시작 전에 앱을 한 번도 안 켠 경우」뿐.
- (948 D3) **끝난 좌석 vs 재시작 복원**을 가르는 근거 = 끝 신호의 유무. 끝 = 앱이 본 닫힘 확인(close_surface 성공) · 데몬 이벤트 surface.exited/closed/reaped · 3초 목록의 exited 표시 → 그 좌석 열쇠(소켓+역할, 없으면 생성 폴더)의 앱 기록을 지운다(열쇠가 그때 하나뿐일 때만). 재시작 = 데몬이 좌석과 함께 내려가 끝 이벤트가 없고 앱은 「모르는 번호」를 유령 수렴으로만 뗀다(detachPane · 기록 무접촉) → 같은 역할로 다시 뜬 좌석이 그 묶음을 이어받는다. ⚠한계: 앱이 꺼져 있는 동안 좌석이 끝나고 같은 역할명이 재배정되면 끝 신호를 못 봐 물려받는다(📌 해결안 = 데몬 정체(pid·시작 시각)가 같은데 열쇠 좌석이 사라졌으면 끝으로 보기 — 이 티켓 밖).
- (948 D2) 탭 화면에서 사람이 만든 새 좌석(⌘T·⌘D)은 지금 보는 탭 묶음에 넣는다 — 앱이 켜져 있는 동안의 기억(열쇠 = 소켓+번호 · 데몬이 정한 묶음만 이를 이김 · 좌석이 끝나면 지움). 앱을 다시 켜면 그 좌석은 자동 규칙(생성 폴더)으로 돌아간다(역할 없는 홈 폴더 좌석은 열쇠가 겹쳐 앱 기록으로 남길 수 없다).
- (948 D7 · master#cb40d4a3) 묶음 이름 규칙(데몬 parse_seat_group = 앱 cleanGroupName): NFKC → 앞뒤 White_Space 자르기 → 64자 이하 · 일반 범주 Cc·Cf·Zl·Zp 가 하나라도 있으면 거부(앱 = 그 이름 없음) · NFKC 된 이름을 저장. 새 의존 unicode-normalization =0.1.26.
- (948 D4) 호출자 게이트: 좌석 안 = master 만 · 좌석 밖 = 조상 체인을 홉 상한(32) 안에서 끝(pid ≤ 1)까지 모두 읽었을 때만 통과(상한 초과·중간 판독 실패 = 거부). 부모 판독 = PROC_PIDT_SHORTBSDINFO(다른 사용자 프로세스도 읽힘 — 사람 터미널의 root /usr/bin/login·launchd · 948 D4-b · 950 caller-audit 과 같은 구현). ⚠알려진 한계: 좌석이 띄운 고아 자식(부모가 launchd 로 바뀜)·다른 데몬 좌석에서 이 소켓을 부르는 것은 「좌석 밖 터미널」 과 구별할 수 없다 — 영향 = 앱 배치·컨트롤 센터 열기뿐(입력·PTY 무접촉). 같은 근거를 쓰는 기존 RPC(surface.close 등) 점검은 master 가 별도 티켓으로.
- 치명 위험 4군 점검(2d): ① 폭주 = 같은 값이면 이벤트를 내지 않음 · 사람/master 명령 1회당 이벤트 최대 1건 · 자동 발신·재시도 고리 없음 ② 무clear = 어느 좌석에도 글을 넣지 않음(입력·주입 경로 무접촉) → 해당 없음 ③ 자가치유 = watchdog·governance 틱·topology·phoenix 무접촉 · 데몬 재시작 시 데몬 필드는 비고(group_set = false = 모름) 앱 기록이 그 자리를 잇는다(948 덧 정정 · 코드 = seatgroup.effectiveGroup) → 해당 없음 ④ 전 pane 사망 = PTY·프로세스 조작 없음 · 좌석 구조체의 문자열 1개를 짧은 잠금으로 씀 → 해당 없음.
