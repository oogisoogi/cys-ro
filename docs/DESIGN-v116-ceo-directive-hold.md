## 0. 한 줄 요약

부서를 만들면 본부 master 지침 파일(`MASTER_DIRECTIVE.md`)이 CEO 지침 사본으로 바뀝니다. 이 파일이 지침 개정을 영영 못 받는 경로가 **둘** 있습니다.

- **경로 1(1085 VM-B)**: 1.1.4 이하 기계에서 부서를 만든 뒤 단추로 갱신하면, 옛 앱이 새 팩을 판정하면서 master 지침을 `.new` 로 보류합니다. 그러고 나면 1.1.5 에 넣은 수리(D1-ⓑ)가 판단 근거를 잃어 다시는 구제하지 못합니다.
- **경로 2(1098 교회 부서 시범)**: 부서가 없는 기계에 예전 승격 때의 백업(`.pre-ceo`)이 남아 있으면 세 가지가 함께 일어납니다.
  - 새로 승격할 때 현행 지침을 백업하지 않습니다.
  - 승격 알림이 꺼집니다.
  - 부서를 다 닫으면 **옛 판 지침이 조용히 되살아납니다**. 이때는 `.new` 도 알림도 없습니다.

### 권고안 세부(구현 계획 · 승인 뒤)
1. **발행 해시 표**(`pack.rs` 상수 `RELEASED_CEO_TEMPLATE_SHA256` · `RELEASED_MASTER_DIRECTIVE_SHA256`는 ⓔ 채택 시): v0.14.x~v1.1.5 태그의 `CEO_TEMPLATE.md` 해시 15종(`scratch/tag-hashes.txt` 에서 생성).
   - 시험 = 「현 임베드 CEO 해시 ∈ 표」(판을 올리고 표를 안 고치면 적색) · 「표의 모든 값 = 64자리 hex」.
2. `ceo_derived_override` 인자에 `receipt_hash: Option<&str>` 를 더한다. 판정 = `dh ∈ {manifest_ceo_before, receipt, 표}`. 치환 content = 신판 CEO(종전 그대로).
   - 영수증은 설치 루프 **전에** 한 번 읽는다(기준값 :3399-3404 와 같은 자리 · 순서 함정 동형).
3. 구제가 일어났을 때(`ceo_ov.is_some()` ∧ 실제 쓰기):
   - ⒜ `.pre-ceo` 동반 전진 조건을 `pre 해시 == manifest[MASTER]` ∨ `pre 해시 ∈ 발행 MASTER 표`(ⓔ 채택 시)로 둔다. 불채택 시 종전 그대로.
   - ⒝ **영수증을 새 CEO 해시로 원자 갱신**(write_atomic) — 영수증이 옛 해시로 남는 문제(성찰 4 ⑴)를 막는다.
   - ⒞ `.new` 파일과 병합 대기 원장의 new-pending 항목 정리. 이미 있는 「정상 갱신 합류 → 잔재 청소」 경로가 이 파일에도 도는지 시험으로 확인하고, 안 돌면 추가한다.
   - ⒟ `.bak-<판번>`: 기존 RefreshUser 백업이 치환 경로에서도 도는지 확인한다.
4. **ⓕ cys-dept**(agy B R1 반영 · 부정 증거 → **긍정 증거**로 교체): 새 함수 `pre_ceo_is_stale` 하나 · 판정은 기존 `ceo_template_superset_ok`(DCE-3 · CRLF 정규화 · argv 경로 전달) 재사용.
   - 술어 `stale` = `.pre-ceo 존재` ∧ `md ≠ CEO_TEMPLATE` ∧ **`CEO_TEMPLATE ⊇ md`**(= md 가 현행 CEO 가 감싼 **현행 표준 원본 그 자체**) ∧ `영수증 ≠ sha256(md)`.
   - 뜻: 「md 가 지금 표준 원본이라는 긍정 증거가 있을 때만」 `.pre-ceo` 를 낡은 백업으로 본다. 증거가 없으면(손수정 CEO 사본 · 핀을 지운 사본 · 손수정 표준본 · 옛 CEO 사본) **종전 동작 그대로**(무접촉)다.
   - 종전 초안(「CEO 표지가 없으면 미승격」 = 부정 증거)은 agy 반례로 폐기했다: 승격 중 사용자가 핀을 지운 CEO 사본에 두 번째 부서를 만들면, 정상 백업이 `.stale-` 로 밀리고 손수정 사본이 `.pre-ceo` 가 돼 강등이 그 사본을 복원한다.
   - 1098 형상 실측 적합: md = 현행 1.1.5 표준 · `CEO_TEMPLATE ⊇ md` = True(1098 A-creation-path.md:149 · repro2 동형) · 영수증 없음 → `stale` 참.
   - `.pre-ceo` 존재를 묻던 세 자리를 모두 「`.pre-ceo` 존재 ∧ ¬stale」(= 유효 백업)로 바꾼다: ⑴부트 마커 PENDING 게이트(:1012) ⑵`_auto`(:1025-1026 → 알림 복구) ⑶`_swap` 백업(:1069).
   - `_swap` 안에서 `stale` 을 **다시** 판정한다(락 안 = 검사·교체 원자 · TOCTOU 차단). 참이면 `mv .pre-ceo .pre-ceo.stale-<YYYYmmddTHHMMSS>` → `cp md .pre-ceo.tmp && mv .pre-ceo.tmp .pre-ceo` → CEO 교체(`cp ceo md.tmp && mv md.tmp md` = 원자 교체).
   - ★**락을 잡지 못한 경로에서는 새 동작을 하지 않는다**(agy B R1 ③ 반영): 윈 mkdir 락 획득 실패 시 기존 코드는 경고 뒤 무락으로 `_swap` 을 강행한다(`cys-dept:1086-1089` · 종전 결함 · 이 티켓 이전부터 있음). 그 경로에서 `.pre-ceo` 를 옮기면 두 프로세스가 백업을 서로 덮을 수 있다 → `_swap` 에 「락 보유」 인자를 넘겨, 무락이면 stale 처리를 건너뛰고 종전 동작만 한다. 무락 강행 자체를 막는 변경(exit)은 부서 생성 흐름의 비치명 계약을 바꾸므로 이 티켓에서는 하지 않고 곁 항목으로 올린다.
5. 원자성: MASTER 교체는 Rust = 이미 `write_atomic` · bash = 임시 파일 + `mv`(같은 디렉터리 rename).
6. 멱등: 10분 틱(`promote-if-pending`) × 설치기 2회 연속 = 파일 해시·알림 변화 0 시험.
