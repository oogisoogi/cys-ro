## §4 함정(이번에 밟은 것)

1. **`make-update-manifest.sh` 는 우리 발행 병합에 쓰면 안 된다.** latest.json 을 통째로 다시 쓰며 darwin 행만 싣는다(윈 행·build_id·pub_date 소실). 읽는 tar 도 tauri 가 낸 dedup 전 번들(약 489 MB)이다. 정본 = `docs/DARWIN-UPDATER-LEGACY-LANE.md` §2: `make-darwin-updater-tarball.sh --app <발행 zip 해제본>` → `make-darwin-update-row.py --merge <CI latest.json> --tarball-url … --tarball-sig "$(cat ….sig)"`.
2. **맥 로컬 빌드에 `CYSR_RELEASE_SEQ=<seq>` 를 넘겨야 한다.** 안 넘기면 build-info `release_seq` 0(미발행)으로 구워진다. 이번 = `CYSR_RELEASE_SEQ=3 scripts/build-macos-local.sh x86_64 <out>`.
3. **좌석 기본 PATH 에 cargo·bun·gh 가 없다.** `export PATH="$HOME/.cargo/bin:$HOME/.bun/bin:/opt/homebrew/bin:/usr/bin:$PATH"` 를 명령마다 앞에 붙였다. `release-postprocess.py` 는 `git credential fill` 을 쓰므로 `/usr/bin/git` 이 PATH 앞에 와야 한다.
4. **zsh 에서 `"$PREV_TAG:src-tauri/…"` 는 변수 수식어(`:s`)로 읽힌다** — `git show` 가 「ambiguous argument 'v1.1.7i.conf.json'」 로 죽고, 빈 파일이 다음 검증기를 다른 사유로 죽인다. 리터럴 태그를 쓰거나 `"${PREV_TAG}:…"`.
5. **`release-postprocess.py` 는 `~/cys-release-backup/<tag>-assets/` 에 받는다.** 그 폴더에 남의 파일(이번 = `…-seq2.zip`)이 있으면 그 폴더를 `release-verify.py --release-dir` 로 주면 안 된다 — 검증은 새 폴더에 `gh release download` 로 다시 받은 바이트에 돌렸다.
6. **`verify-release-remote.py` 는 원작자 홈페이지(SITE = cysinsight) 전용이다.** 우리 발행 대조에 못 쓴다. 공개 대조 = 공개 자산 재다운로드 + SHA256SUMS + 공개 latest.json·봉투 sha.
7. **자동 갱신 판정 명령의 철자 = `cys self-update --check`**(브리프의 `self-update-check` 는 없는 동사).
8. **발행 레인 `--ref`**: environment `release-production` 허용 가지(fix/117-int · main · rebase/v0.14.30 · rebase/v1.0.0 · rebase/v1.0.1 · rebase/v1.0.2 · rebase/v1.1) 가운데 그 판의 검증 도구가 있는 가지여야 한다. 1.1.8 = main 뿐.
9. **발행 도구의 HTTP User-Agent**: 공개 호스트는 `Python-urllib/…` UA 를 403 으로 막는다(이 맥 실측 · `update_common.py:34` 기지). curl 기본 UA 는 200. 러너의 403 은 UA 가 아니라 출발지 기준(Bot Fight Mode).
