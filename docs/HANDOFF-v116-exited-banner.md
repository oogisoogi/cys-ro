## §2 원인(대조군 2개로 확정)

- `ui/src/main.ts:3427`(3bc73856) — `term.write("\r\n\x1b[31m[surface exited]\x1b[0m\r\n", snapToBottom)` 는 배너를 **커서가 있던 줄의 다음 줄**에 쓴다.
- 좌석 프로그램이 커서를 화면 중간(입력 상자 · 대체 화면 TUI의 입력 칸)에 둔 채 끝나면, 그 아래 내용 위에 배너가 덮어써져 「중간에 뜬다」. 대조군에서 **커서 위치 하나만** 바꾸면 배너가 맨 아래로 간다.
- 같은 줄은 v1.0.2(54c148cc) `:3004` · v1.1.5(526325bf) `:3368` 에서 같다(브리프 관측) ⇒ 박사님이 본 1.0.2 화면과 같은 코드.

## §3 수리 설계

- 배너를 쓰기 **직전** 화면(활성 버퍼 — 주 화면이든 대체 화면이든)에서 「커서 줄과 그 아래 마지막 내용 줄 중 더 아래」를 찾아 그 줄로 커서를 옮긴 뒤 배너를 쓴다.
  - 커서 아래에 내용이 없으면 지금과 **똑같다**(⒞ ⒟ a0 b0 의 화면이 바뀌지 않음 — 외과적).
  - 판독은 앞선 쓰기(필터 잔여 방류 · 정합기 reset)가 **해석된 뒤**(xterm `write` 콜백)에 한다 — 대기열에 남은 출력이 있는 채로 읽으면 틀린다.
  - 이동 전에 스크롤 영역(DECSTBM)을 `ESC[r` 로 전체 화면으로 되돌린다 — 죽은 앱이 남긴 스크롤 영역(·원점 모드)이 있으면 「맨 아래로」 이동이 영역 안에 갇히거나 마지막 줄 줄바꿈이 스크롤되지 않아 배너가 덮어쓴다. 원점 모드(DECOM)는 영역이 전체 화면이면 원점 = 1행이라 따로 끄지 않는다(초안의 `ESC[?6l` 은 헤드리스에서 등가로 확인되어 뺐다). 스트림은 종료 이벤트 뒤 다시 열리지 않으므로(`makePane` 멱등 · `start_surface_stream` 은 `makePane` 에서만) 이 해제가 산 앱의 그리기를 깨지 않는다.
- **대체 화면은 풀지 않는다**(1049l 미포함 유지): 풀면 죽은 TUI의 마지막 화면(오류 문구일 수 있음)이 사라지고 옛 주 화면이 나온다. 정합기 reset 의 「1049l 미포함」 원칙과도 같은 편.
- 배치: 순수 판정 + 쓰기 순서를 새 leaf 모듈 `ui/src/exitbanner.ts` 에 두고 `main.ts` 는 배선 1줄(단위 시험이 순서·위치를 직접 잰다).
- 고른 까닭: 「무조건 마지막 행으로」 안은 내용이 짧은 화면(⒟)에서 배너가 멀리 떨어진 맨 밑으로 튀어 지금 멀쩡한 화면까지 바꾼다. 「화면 밖 표시(머리표 배지)」 안은 박사님이 익숙한 빨간 줄을 없애고 UI 층을 넓힌다. 「내용 뒤로」 안이 지금 옳은 경우를 하나도 바꾸지 않고 틀린 경우만 고친다.

## §8 기록만(고치지 않은 것 · 사유)
- NIT-1 배경색만 칠한 빈 줄은 빈 줄로 본다 — 배너가 그 위에 앉으면 배경색이 남을 수 있음. 관측 사례 없음 · 판정에 속성까지 넣으면 복잡도가 커짐.
- NIT-2 판독~배너 해석 사이 리사이즈(쓰기 예산 12ms 가 reset 청크에서 끊길 때만) — 소스 추론 · 확률 매우 낮음 · c18j 초록.
- NIT-3 콜백 안 예외가 xterm 대기열을 멈출 수 있음 — `snapToBottom` 콜백은 종전에도 같은 노출(새 노출 아님).
- NIT-4 dispose 뒤 콜백 — 배너 2회·우리 코드 예외 불가(판독 try).
- **미결(3R 새 지적 · master 지시로 미수정 — master 판정 대상)**: NIT-5 16열 미만 창에서 배너 행이 마지막 행이면 배너 글이 접혀 맨 윗줄 1줄 스크롤 소실(대체 화면) · 죽은 앱이 자동 줄넘김을 끈 경우(ESC[?7l) 배너 잘림. NIT-1 확장 = 배경 전체를 칠하는 TUI 에서 대체 화면 배너가 색칠된 빈 줄(중간)에 앉을 수 있음(글 덮어쓰기·줄 손실 0).
- agy 2R ③ 판독 실패 강등(대체 화면 가득일 때 2줄 손실) — 예외 경로 한정.
- 종료 이벤트 2회 1배너는 조건부(opus 2R) — 실경로 1회.
- 곁 항목(범위 밖): 데몬 재시작(EOF)에도 종료 이벤트가 발화해 산 창에 배너가 남는 것은 종전과 같음(T-UI 메모리 `cysr-ui-exited-signal-and-headless-traps`).
