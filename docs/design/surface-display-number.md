## 1. 한 장 요약

좌석에는 번호가 **두 개** 있게 된다.

| | 내부 번호 | 보이는 번호 |
|---|---|---|
| 모양 | `surface:1049`(지금과 똑같음) | `50`(창 제목 「50 · worker1」) · 사람이 칠 때는 `#50` |
| 범위 | 1부터 한없이 커짐(u64) · **절대 다시 쓰지 않음** | 1~999 · 돌아서 다시 씀 |
| 쓰는 곳 | 기계가 쓰는 모든 곳 — 닫기·입력·배달·권한·기록·인박스·원장·환경변수 | 사람 눈 — 창 제목 · `cys list` 한 열 · 알림 문안 · 사람이 치는 `#N` |
| 정하는 법 | 지금 그대로(`next_id.fetch_add`) | **내부 번호에서 계산한 자리**를 먼저 보고, 쓰는 중이거나 24시간 안에 닫힌 번호면 다음 빈 번호 |

핵심은 두 가지다.
- **기계는 보이는 번호를 받지 않는다.** 닫기·입력 같은 파괴적인 명령은 지금처럼 내부 번호만 받는다. 사람이 `#50` 이라고 치면 CLI 가 **먼저** 「지금 살아 있는 좌석 중 보이는 번호가 50인 좌석」의 내부 번호를 물어보고, 그 내부 번호로 명령을 보낸다. 못 찾으면 **거부**한다(추측해서 다른 좌석으로 보내지 않는다).
- **내부 번호 1~999 인 좌석은 보이는 번호가 내부 번호와 같다**(불변식 I1 · §2-3). 그래서 누군가 실수로 보이는 번호를 내부 번호 자리에 넣어도(`cys close-surface 50` · 스크립트가 `display_no` 를 `surface_id` 로 넘김) **같은 좌석에 닿거나 「없음」으로 끝난다 — 다른 산 좌석에는 절대 닿지 않는다.** 이것이 4군 ④(전 pane 사망)를 설계 단계에서 닫는 근거다.

## 2. ⑴ 할당기 규칙

### 2-1. 후보 자리와 탐색

좌석을 만들 때(내부 번호 `id` 를 받은 바로 그 자리에서) 보이는 번호를 정한다.

1. **후보** `c = ((id − 1) mod 999) + 1`. — 내부 번호 1~999 는 자기 자신, 1000 → 1, 1049 → 50, 1998 → 999, 1999 → 1.
2. **막힌 번호**: 번호 `n` 의 마지막 주인이 ⑴ 아직 좌석 목록에 있다(산 좌석 · 끝났지만(exited) 아직 회수 안 된 좌석 포함) 또는 ⑵ 닫힌 지 W(24시간) 가 **안 됐다**(`now − closed_at < W` · 엄격한 미만 — 정확히 24시간이 지난 순간부터 다시 쓸 수 있다).
3. `c` 가 막혀 있지 않으면 `c` 를 준다. 막혀 있으면 `c+1, c+2, …, 999, 1, 2, …, c−1` 순서로 **처음 비어 있는 번호**를 준다.
4. **I1 보호 규칙**: `id ≤ 999` 인데 `c(= id)` 가 막혀 있으면 탐색하지 않고 **번호 없음(「—」)** 으로 만든다 + 경보 1줄. (정상이라면 일어날 수 없다 — 증명 §2-3. 일어났다면 내부 번호가 재사용됐다는 뜻이므로(대응표 쓰기 실패 등) 조용히 다른 번호를 주지 않고 드러낸다.)
5. **다 찼을 때**(999개가 모두 막힘): 번호 없음(「—」)으로 좌석을 **만든다**. ⛔좌석 생성을 막지 않는다(4군 ③). 경보 = 데몬 로그 1줄 + 이벤트 `surface.display_exhausted` 1건(다 찬 상태가 풀릴 때까지 한 번만). 번호 없는 좌석은 평생 「—」 다(나중에 번호를 끼워 넣지 않는다 — 사람이 보던 번호가 바뀌는 쪽이 더 헷갈린다).
6. **좌석 생성이 실패한 번호**(PTY 를 못 열었음): 그 행은 곧바로 닫힘(`close_kind='spawn_failed'`)으로 적고, 할당기는 이 행을 **막힘으로 치지 않는다**(사람이 본 적 없는 번호라 건너뛸 이유가 없다). 내부 번호는 지금처럼 소모된다(재사용 없음 유지).

**왜 「직전 번호 + 1」이 아니라 「내부 번호에서 계산한 자리」인가** — 두 방식 모두 1~999 를 돌지만, 후자만 불변식 I1 을 준다. 「직전 + 1」 방식은 부서 데몬처럼 내부 번호가 작은 곳(dept-1 최대 30 · PLAN §4-1 【관측】)에서 보이는 번호와 내부 번호가 어긋나고, 그러면 맨숫자 `31` 이 「보이는 31」과 「내부 31(= 보이는 1)」 두 좌석을 가리키게 된다 — 사람이 보이는 번호를 맨숫자로 치는 순간 **다른 산 좌석이 닫히는 길**이 열린다(§5-4 반례 R-9).

### 2-2. 시각

- `created_at`·`closed_at` 은 벽시계 epoch 초(`f64` · 지금 `Surface.created_at` 과 같은 단위 · state.rs:797). 재기동을 건너 살아남아야 하므로 단조 시계는 못 쓴다.
- 시계가 **뒤로** 가면(`closed_at` 이 미래) `now − closed_at` 이 음수라 막힘으로 남는다 — 보수적(재사용이 늦어질 뿐).
- 시계가 **앞으로** 뛰면 24시간 전에 번호가 풀릴 수 있다 — 결과는 「사람이 옛 번호를 떠올릴 때 헷갈릴 수 있음」뿐이다. 내부 번호는 영향이 없으므로 명령이 다른 좌석에 닿는 일은 없다(§3 · I1). 잔여 위험으로 적는다(§5-4 R-5).

### 2-3. 불변식과 증명

- **I0 (내부 번호 비재사용)**: 한 데몬(소켓)의 내부 번호는 대응표가 생긴 뒤 다시 나오지 않는다. — 대응표 행을 **PTY 를 열기 전에** 동기로 쓰고(§3-2), 재기동 시드가 대응표의 최대값까지 본다(§6). 쓰기 실패 때는 경보(§3-2 ⑤).
- **I1 (작은 내부 번호는 제 번호)**: 살아 있는 좌석 `s` 에 대해 `s.id ≤ 999` ⇒ `s.display_no ∈ {s.id, 없음}`.
  - 증명【추론】: `id ≤ 999` 인 좌석을 만드는 순간, 이미 있는 행들은 모두 내부 번호가 `id` 보다 작다(I0). 귀납 가정으로 그 행들의 보이는 번호는 제 내부 번호이거나 없음이다 → 보이는 번호 `id` 를 가진 행이 없다 → 후보 `c = id` 는 막히지 않는다. I0 이 깨진 경우는 §2-1 ④ 보호 규칙이 「없음」을 줘서 I1 을 지킨다. ∎
- **I2 (산 좌석끼리 보이는 번호가 겹치지 않음)**: 쓰는 중 번호는 막힘이다(§2-1 ②⑴).
- **I3 (한 보이는 번호의 수명 구간이 겹치지 않음)**: 번호 `n` 의 새 주인은 옛 주인이 닫히고 W 가 지난 뒤에만 생긴다 → 구간 `[created_at, closed_at + W)` 가 서로 겹치지 않는다 → 옛 기록의 「(보이는 번호 n, 시각 t)」는 대응표에서 **하나의** 내부 번호로 풀린다(PLAN §4-4 ⑥).
- **따름정리 S (보이는 번호를 내부 번호 자리에 넣어도 다른 산 좌석에 안 닿음)**: 누군가 보이는 번호 `n` 을 내부 번호로 쓰면 → 내부 `n` 이 죽었으면 「없음」, 살았으면 I1 에 따라 그 좌석의 보이는 번호도 `n` 이고 I2 에 따라 보이는 번호 `n` 의 주인은 그 좌석 하나뿐 → **의도한 그 좌석**. ∎

## 3. ⑵ 대응표 스키마

### 3-1. 표

`transcripts.db`(데몬마다 따로 · recall.rs:20-22 `db_path` · 같은 파일에 lines·chains 가 있다)에 **표 1개를 추가만** 한다. 기존 표 무변경 · 이관 없음(비가역 결정 목록 해당 없음 — 브리프 「새 표 추가만 = 가역」).

```sql
CREATE TABLE IF NOT EXISTS surface_numbers(
  surface_id  INTEGER PRIMARY KEY,  -- 내부 번호(재사용 없음 · I0)
  display_no  INTEGER,              -- 1..999 · NULL = 「—」(다 참 · I1 보호)
  created_at  REAL NOT NULL,        -- 벽시계 epoch 초
  closed_at   REAL,                 -- NULL = 쓰는 중(또는 기록 전 데몬이 죽음 → 부팅 때 채움)
  close_kind  TEXT,                 -- 'close' | 'spawn_failed' | 'boot_orphan'
  socket      TEXT NOT NULL         -- 이 행을 만든 데몬 소켓(자기 설명용 · 판정에는 안 씀)
);
CREATE INDEX IF NOT EXISTS surface_numbers_by_display
  ON surface_numbers(display_no, surface_id);
```

- 스키마 자리 = recall.rs:24-55 `open_db` 의 `execute_batch` 에 덧붙인다(같은 `CREATE … IF NOT EXISTS` 관례).
- `socket` 칸은 브리프가 적은 5칸 중 하나다. DB 가 이미 데몬마다 따로라 판정에는 쓰지 않는다 — 파일을 옮기거나 합쳤을 때 어느 데몬의 행인지 알아보는 용도.
- **정리(prune)하지 않는다**(1.1.6). 크기 【추정】: 평균 하루 ≈16개 · 가장 바쁜 날 106개(PLAN §4-1 【관측】) → 1년 6천~3만9천 행 · 행당 수십 바이트 → 수 MB 이하. recall 의 `maybe_prune`(recall.rs:199)은 이 표를 건드리지 않는다(시험 T10).

### 3-2. 쓰는 때와 방법

| 사건 | 무엇을 | 어디서(526325bf) | 방법 |
|---|---|---|---|
| 좌석 만들기 | 내부 번호 받기 → 보이는 번호 정하기 → **행 INSERT** → 그 다음 PTY 열기 | state.rs:3483 `create_surface_with_env` · :3502 `fetch_add` 바로 뒤 · PTY 는 :3503~ | **동기 쓰기**(전용 연결 · `busy_timeout`). recall 쓰기 스레드(1초 묶음 · recall.rs:86~)를 거치지 않는다 — 묶음 사이에 데몬이 죽으면 그 내부 번호가 기록 없이 사라져 X-10 이 다시 열린다 |
| PTY 열기 실패 | `closed_at = now` · `close_kind='spawn_failed'` | 같은 함수의 `?` 반환 경로들 | 동기 UPDATE |
| 좌석 닫기 | `closed_at = now` · `close_kind='close'` | governance.rs:4885 `close_surface` — 좌석이 목록에서 빠지는 **유일한 자리**(주석 governance.rs 같은 함수 「surface가 맵에서 사라지는 유일 지점」 【관측】) | surfaces 락을 푼 **뒤** 동기 UPDATE |
| 데몬 부팅 | `closed_at IS NULL` 인 행 전부 `closed_at = 부팅 시각` · `close_kind='boot_orphan'` | state.rs:3000 `next_id` 시드 옆(Daemon 생성) | 새 좌석을 만들기 **전에** 1회 |

- ①**왜 PTY 전에 쓰나**: 자식 프로세스는 생성 순간 환경변수로 내부 번호를 받는다. PTY 를 연 뒤에 쓰면 「내부 번호는 밖으로 나갔는데 기록은 없다」 틈이 생긴다(PLAN §4-2 CLI 행: pane 이 죽은 뒤 살아남은 백그라운드 프로세스).
- ②**락 순서**: 할당기 상태는 **잎(leaf) 락** `display_alloc` 하나에 둔다. 좌석을 만들 때 `display_alloc` 을 잡고 `fetch_add` → 후보 계산 → INSERT → 놓기. surfaces·roles 락을 쥔 채로 잡지 않는다(닫기에서는 surfaces 락을 푼 뒤 잡는다). DB 쓰기가 이 락 안에서 일어나 좌석 생성이 직렬화되지만 생성 빈도(하루 최대 106 · 동시 버스트 수 개)에서 무시할 수준이다 【추정 · 실측 없음 — 구현 티켓 ②에서 생성 지연 1줄 실측】.
- ③**메모리 상태**: `holders[1..=999]` = 번호마다 마지막 주인 `(surface_id, closed_at: Option<f64>)`. 부팅 때 표에서 번호마다 내부 번호가 가장 큰 행으로 채운다(`spawn_failed` 행 제외).
- ④**보이는 번호를 좌석에 붙이는 곳**: `Surface` 에 `display_no: Option<u16>` 필드(state.rs:787 구조체) — 한 번 정하면 바뀌지 않는다.
- ⑤**DB 쓰기가 실패하면**(디스크 가득 · 잠김 시간 초과): 좌석은 **만든다**(4군 ③) · 메모리 할당기로 번호를 정한다 · 경보 1줄(`surface.numbers_write_failed`). 그 좌석은 I0 보호가 빠진 상태(재기동 뒤 내부 번호 재사용 가능)라는 것을 경보 문구에 적는다. 이때도 I1 은 §2-1 ④ 보호 규칙이 지킨다.
- ⑥**보이는 번호를 환경변수로 내보내지 않는다**(`CYS_SURFACE_ID` 는 지금처럼 내부 번호). 자동화가 보이는 번호를 열쇠로 쓰기 시작하는 입구를 처음부터 만들지 않는다.

### 4-2. `#N` 해석기 — 사람 입력을 내부 번호로

- **문법**(lib.rs 에 새 함수 `parse_display_ref`): `#` + 십진수 1~999. 앞뒤 공백만 허용(`trim`). `#0` · `#1000` · `#-1` · `# 17` · `#17a` · `#017`(앞자리 0) 은 **거부**. `surface:` 문법과 섞지 않는다(`surface:#17` 거부).
- **어디서 푸나**: CLI 만. cys.rs 에 `resolve_surface_arg(s) -> Result<u64, String>` 하나를 두고 — `parse_display_ref` 가 맞으면 RPC `surface.resolve_display` 로 내부 번호를 받아 오고, 아니면 지금처럼 `parse_surface_ref`. 사람 입력을 받는 좌석 인자(§4-1 표의 14곳)를 이 함수로 바꾼다. 환경변수 폴백(`CYS_SURFACE_ID`)은 이 함수를 거치지 않는다(원래 내부 번호다).
- **푸는 범위**: 그 CLI 가 말하는 **데몬 한 곳의 · 지금 좌석 목록에 있는 좌석**만. 닫힌 번호 · 옛 번호 · 다른 데몬은 풀지 않는다.
- **거부(추측 금지)**:
  | 경우 | 결과 | 문구(초안) |
  |---|---|---|
  | 문법 밖(`#0`·`#1000`·`#abc`) | 오류 · RPC 0회 | 「보이는 번호는 #1~#999 입니다」 |
  | 지금 그 번호의 좌석이 없음 | 오류 · 뒤따르는 명령 RPC 0회 | 「#17 인 좌석이 지금 없습니다(마지막 주인 surface:1016 · 3시간 전 닫힘). 다른 좌석으로 보내지 않습니다.」 |
  | 번호 없음(「—」) 좌석을 가리키고 싶음 | `#` 로는 불가 · 내부 번호 `surface:N` 으로 | — |
- **해석과 명령 사이(TOCTOU)**: 해석이 돌려준 것은 **내부 번호**다. 그 사이 좌석이 닫혀도 내부 번호는 다시 쓰이지 않으므로(I0) 명령은 「없음」으로 끝난다 — 다른 좌석에 닿지 않는다.
- **맨숫자**(`17`)는 지금처럼 **내부 번호**다(스크립트·기존 관행 보존). 사람이 보이는 번호를 맨숫자로 잘못 쳐도 따름정리 S 에 따라 같은 좌석이거나 「없음」이다.
- **셸의 `#`**: bash 와 PowerShell 은 단어 첫머리 `#` 를 주석으로 먹는다(zsh 는 기본 설정에서 주석이 아니지만 설정(interactive_comments·extended_glob)에 따라 달라진다). 따옴표 없이 `cys close-surface #17` 을 치면 `cys close-surface` 만 남는다. 【관측】 cys.rs 에서 좌석 인자는 ⑴선택 인자는 전부 `--surface` 긴 플래그(값이 사라지면 clap 이 「값 필요」 오류) ⑵위치 인자(`CloseSurface.surface` · `ReapSurface.surface` · cys.rs:317-331)는 **필수**(사라지면 clap 오류) → **환경변수 폴백으로 새지 않는다** — 결과는 오류이지 자기 좌석 닫기가 아니다. 안내 문서에는 `'#17'` 처럼 따옴표를 쓰라고 적는다. (`--surface=#17` 은 단어 첫머리가 아니라 그대로 전달된다.)

## 12. 4군 점검

1. **① 폭주 큐** — 보이는 번호는 큐 열쇠에 들어가지 않는다(큐는 내부 번호·role 로 움직임 · PLAN §4-7 【관측】). 새로 쓰는 DB 는 좌석 만들기·닫기·부팅에만 쓰고 배달 경로에는 없다. **해당 없음.**
2. **② 무clear 100%+** — 컨텍스트·순환 경로를 건드리지 않는다. **해당 없음.**
3. **③ 자가치유 전멸** — 다 찼을 때(「—」) · DB 쓰기 실패 때 · I1 보호 때 모두 **좌석을 만든다**. 할당기 락은 잎 락이고 surfaces 락을 쥔 채로 I/O 하지 않는다. T5 ⑶ 이 「생성이 한 번도 안 막힘」을 확인한다. **새 막힘 경로 0.**
4. **④ 전 pane 사망(핵심)** — 보이는 번호가 닫기·입력 RPC 로 들어가는 길이 **설계에 0**이다: ⑴데몬 RPC 입구(`resolve_surface_id` → `parse_surface_ref`)는 무변경이라 `#N` 을 거부(T3) ⑵파괴 RPC 는 `display_no` 인자를 읽지 않음(T3b 소스 핀) ⑶사람의 `#N` 은 CLI 에서 **산 좌석만** 내부 번호로 풀고 못 풀면 거부(T9) ⑷보이는 번호를 내부 번호 자리에 잘못 넣어도 I1·I2 로 같은 좌석 또는 없음(따름정리 S · T4) ⑸해석과 명령 사이 경합도 I0 로 없음 ⑹X-10 을 닫아 D4 의 「번호 재사용 없음」 전제(D4-ui.md:80)가 **더 강하게** 참이 된다. 남는 것은 「사람이 번호를 잘못 고름」뿐이다(시스템 누출이 아님).
