FINDINGS:
- [심각도 중간] <§2-1> I1 보호 규칙(④) 및 번호 정지 규칙은 도달할 수 없는 죽은 코드임 — 근거: I0가 깨져 시드가 0이 되더라도 빈 `holders` 메모리로 시작하므로 `id`가 1~999로 증가할 때 후보 `c(=id)`가 막히는 일은 절대 없음. 정상 부팅 시에도 시드는 기존 기록의 최대값이므로 새 좌석의 `id`는 항상 과거 기록보다 커서 충돌하지 않음. T4의 M26 시험은 실행 중 `next_id`가 뒤로 가는 비현실적 상태를 주입했을 뿐임. — 제안: 도달 불가능한 §2-1 ④ 규칙과 복잡도만 높이는 §2-3 번호 정지(numbers_suspended) 로직을 모두 삭제할 것. 불변식 I1과 S는 이 방어선 없이도 무조건 성립함.
- [심각도 중간] <§3-2> 할당기 잎 락(`display_alloc`) 안에서 동기 DB INSERT 수행 시 비동기 런타임 지연 위험 — 근거: INSERT를 락 안에서 수행하면 SQLite I/O 대기(예: prune 중 최대 5초) 동안 락을 쥔 상태가 됨. 이때 다른 좌석이 종료되어 `close_surface`가 메모리 갱신을 위해 락을 요청하면, 비동기 스레드 전체가 최장 5초간 블로킹되어 시스템 지연을 유발할 수 있음. — 제안: 메모리(`holders`)를 먼저 `Live(id)`로 갱신하고 락을 푼 뒤(락 밖에서) DB INSERT를 수행할 것. 쓰기 실패 시 PTY 실패 복구(③)와 동일하게 락을 다시 잡아 이전 상태(`prev`)로 되돌리거나, 현재 설계처럼 메모리를 그대로 유지하면 됨.
