`[MED] §3-2 「데몬 부팅」 ⑵⑶⑷ · §6 · T2/T13` — Putting the `surface_numbers` seed read + holders rebuild in the *same* transaction as the ⑶ `boot_orphan` UPDATE couples two reads to a write that legitimately fails on exactly the fixture class T13 uses (read-only DB file; also disk-full at boot). With the full schema already present, ⑴ `open_db` succeeds (PRAGMA on an already-WAL file and `CREATE … IF NOT EXISTS` on existing tables need no write), ⑵ reads succeed, then ⑶ returns `SQLITE_READONLY`/`SQLITE_FULL` — SQLite starts the write transaction at statement start, so this happens even when 0 rows match (INFERENCE on the 0-row point; documented for read-only in general). The doc only says "surface_numbers 갈래가 `Failed` 면 holders 는 비운다"; it does not say what happens when the read was `Ok` and the tx aborts on ⑶. A conforming implementation that discards the rolled-back tx's results gets: seed = max(lines, chains)+1 — which can be **below** the `surface_numbers` max (X-10 seats that wrote no lines), holders **empty** so §2-1 ④ has nothing to block on (no "—", no suspension), and — since the read itself was `Ok` — possibly **no `seed_failed` alarm**. Net: I0 and I3 broken silently on a read-only/full disk, the case the alarm design exists for. — fix: split the two concerns. Reads (⑵ surface_numbers branch + ⑷ holders) in one deferred read transaction = single snapshot = authoritative; ⑶ UPDATE afterwards, best-effort. On ⑶ failure keep seed/holders from the snapshot, mark orphan rows `Closed(부팅 시각)` in memory anyway (§3-2 ③ already says memory is the source of truth; unwritten orphans are simply re-orphaned at the next boot — harmless, 24 h blocked again), and emit one `numbers_alarm{kind:"write_io"}` (no `surface_id`) rather than `seed_failed`. Add T2 ⑹: read-only DB with surface_numbers rows → seed = surface_numbers max+1 · those numbers blocked · alarm `write_io` not `seed_failed`; mutant M11e "tx failure discards reads" → red. Also state in T13 that the fixture must carry the full schema *before* being made read-only, otherwise ⑴'s `CREATE TABLE surface_numbers` fails and a `seed_failed` alarm appears next to the asserted single `write_io` (the "1건" assertion depends on this).
