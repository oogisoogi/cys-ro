# 팩 훅이 Claude 작업 전체를 느리게 하던 문제 — 진단 확인과 수리(1.1.11) · 원작자 공유용 1쪽

**보내 주신 진단은 전부 맞았습니다.** 그대로 재 보았고, 하나를 더 찾았습니다. 수리는 「개인 작업은 설정 폴더를 따로 쓰라」고 사용자에게
맡기는 대신, 팩이 개인 설정에 손대지 않게 하는 쪽으로 했습니다.

## 무엇을 쟀나(맥 · 격리 시험 폴더 · 각 20회)
- 설치하면 `~/.claude/settings.json` 에 팩 훅 20개 + 상태줄 1개가 붙는다. 시간 제한 선언은 4개뿐(나머지는 기본 600초).
- 사용자가 cys 와 상관없이 쓰는 Claude 세션에서도 도구를 쓸 때마다 팩 훅이 돈다 — 도구 1회당 약 40ms, 답이 끝날 때마다 약 70ms.
- 답 뒤 훅(Stop)은 Claude 가 끝날 때까지 기다린다. 실제 기록: 1,720회 중 1초 이상 810회, 10초 이상 19회, 최장 818초.
  다른 기록에서는 답 뒤 훅 2개가 17.6분 붙어 있다가 취소된 사례도 있었다(대조 실험으로는 재현되지 않아 원인은 미확정).
- **추가 발견**: 세션 시작 훅(inject-context)이 cys 와 무관한 세션에도 cys 의 정체 문구와 「지시가 없으면 대기로 보고하고 턴을 끝낸다」를
  넣고 있었다(최근 14일 112회 · Claude 데스크톱 앱 세션 포함). 속도보다 이쪽이 더 큰 문제다.

## 무엇을 고쳤나
1. **개인 설정에는 기본으로 걸지 않는다.** cys 좌석은 원래 자기 전용 설정 폴더(`~/.cys/claude`)를 쓴다. 개인 설정(`~/.claude`·`~/.claude-*`)에는
   사용자가 표지 파일(`~/.cys/local/hooks-personal-profiles`)을 둔 경우에만 건다. 표지가 없으면 업데이트 때 **이미 붙은 팩 훅만 걷어낸다** —
   사용자 훅과 다른 설정은 글자 하나 바꾸지 않는다(키 순서·들여쓰기·BOM·CRLF 그대로 · 읽기 전용으로 잠근 파일은 손대지 않음 · 손대기 전 사본 저장).
2. **좌석이 아닌 세션에서는 팩 훅이 아무것도 하지 않는다.** 좌석 표시(환경 변수)가 없으면 첫 줄에서 끝난다 — 도구 1회당 약 5ms, 출력 0.
   그래서 표지를 둔 기계에서도 개인 세션은 깨끗하다.
3. **답 뒤에 기다리지 않는다.** 답 뒤 저장·점검 훅은 뒤에서 따로 돌고 Claude 는 바로 끝난다. 실제 Claude Code 로 잰 결과: 8초 걸리는 일을
   붙였을 때 10.1초 → 2.6~3.3초, 뒤에서 돈 결과는 4번 모두 남았다. 막는 역할의 훅(질문 게이트)만 그대로 기다린다.
4. **모든 팩 훅에 짧은 시간 제한**(10초 · 압축 직전 저장만 30초). 실측 최악이 0.3초라 넉넉하고, 무언가 걸려도 10분씩 멈추지 않는다.

## 되돌리기
- 걷어낸 설정 되돌리기: `cp ~/.claude/settings.json.bak-cys-hookslim-<숫자> ~/.claude/settings.json`
- 개인 설정에도 다시 걸고 싶으면: `touch ~/.cys/local/hooks-personal-profiles`
- 답 뒤 훅을 예전처럼 기다리게: 환경 변수 `CYS_HOOK_STOP_SYNC=1`

## 검증
상태 11가지(새 설치·옛 설치·사용자 훅과 섞임·사용자 훅만·깨진 파일·읽기 전용·여러 프로필·표지 있음·윈도우 모양 파일·두 번 실행·되돌리기)를
실제 프로그램으로 격리 폴더에서 돌려 전후를 글자 단위로 대조했다. 윈도우 실측은 진행 중이다.

원작자 쪽 패치가 나오면 이 수리와 나란히 놓고 더 나은 쪽을 고르겠습니다. 이 요약과 설계 문서(`docs/DESIGN-hook-slim-1111.md`)는 그대로 쓰셔도 됩니다.
