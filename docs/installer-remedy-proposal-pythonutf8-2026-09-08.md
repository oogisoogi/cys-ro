# 설치기 임시 처방 제안 — 사용자 환경변수 `PYTHONUTF8=1`

> **상태 = 제안(문안·근거)입니다. 코드는 이 티켓 범위 밖입니다**(대상 저장소 = `jarvis-habitat`
> `install-master/` · 별도 발주). 여기서 결정할 것은 「이 처방을 채택할 것인가」이고,
> 채택되면 그 저장소에서 구현합니다. 작성 = TICKET=cys-phoenix-korean-windows · 2026-09-08.

## 1. 무엇을 고치려는 것인가

한국어 Windows 에서 콜드부트 피닉스가 로케일 코덱(cp949)에 묶여 즉사합니다(상세 = 같은 날짜의
`upstream-pr-draft-phoenix-korean-windows-2026-09-08.md`). 우리 포크는 커밋 `07ab986` 에서
이것을 **코드로** 고쳤습니다 — 팩 파이썬이 자기 스트림과 파일 인코딩을 스스로 못박고, 데몬이
파이썬을 스폰할 때 `PYTHONUTF8=1` 을 싣습니다.

문제는 **참가자가 받는 것이 우리 포크가 아니라 벤더 배포본(0.14.29)** 이라는 점입니다. 그 빌드에는
이 수리가 없습니다. PR 이 병합돼 다음 배포에 실릴 때까지, 참가자 기계는 계속 이 병을 앓습니다.

이 문서가 제안하는 것은 그 **사이 기간의 임시 처방**입니다: 설치기가 그 기계의 사용자 환경변수에
`PYTHONUTF8=1` 을 등록해, 벤더 빌드가 스폰하는 파이썬도 UTF-8 모드로 뜨게 하는 것.

## 2. 제안 내용

| 항목 | 값 |
|---|---|
| 무엇 | 사용자 환경변수 `PYTHONUTF8` = `1` |
| 대상 | `[Environment]::SetEnvironmentVariable('PYTHONUTF8','1','User')` — **User** 범위 |
| 권한 | 관리자 **불요**(User 범위는 일반 사용자가 쓸 수 있습니다) |
| 넣는 자리 | `bootstrap.ps1` `[8/11]`(계정 준비) — cys 자리를 잡는 단계 |
| 코드 선례 | 같은 파일 `Seed-LocalBinPath`(`[2/11]` · 사용자 `Path` 조각 등록 · `bootstrap.ps1:487`) |
| 지우는 자리 | `reset-clean.ps1` — 선례 = `Remove-UserPathSeed`(`reset-clean.ps1:336~350`) |
| footprint ID | **신설 `W-PYUTF8`** — `install-master/footprint.md` §2 표에 한 줄 추가 |

### 2-1. footprint 표에 넣을 줄(초안)

```
| `W-PYUTF8` | 파이썬 UTF-8 모드 | **사용자** 환경변수 `PYTHONUTF8` | 남의 파일 속 우리 줄 | `[8/11]` `Seed-PythonUtf8` | 코드 |
```

종류를 **「남의 파일 속 우리 줄」**로 두는 것이 이 제안의 핵심 안전 조항입니다. 환경변수 공간은
그 사용자의 것이고, **`PYTHONUTF8` 을 이미 갖고 있는 사용자가 있을 수 있습니다.** 그러므로:

- 설치기는 **기존 값이 있으면 덮어쓰지 않습니다.** 있으면 그대로 두고 화면에 그렇게 말합니다.
- 설치기가 **없던 것을 만들었을 때만** 그 사실을 기록하고, 제거기는 **그때만** 지웁니다.
- 이 기록이 없으면 제거기는 「우리가 만든 1」과 「원래 있던 1」을 구별할 수 없어, 남의 설정을
  지우게 됩니다 — footprint.md 머리말이 경고하는 바로 그 갈래 혼동입니다.

## 3. 부작용 — 정직하게

**이 변수는 그 사용자의 다른 모든 파이썬 프로그램에도 적용됩니다.** cys 만 골라 켜지지 않습니다.

구체적으로 UTF-8 모드는 `open()` 의 기본 인코딩을 로케일 코덱에서 UTF-8 로 바꿉니다. 그래서
**cp949 로 저장된 파일을 인코딩 인자 없이 읽던 그 사용자의 프로그램이 깨질 수 있습니다.**
한국어 Windows 에서 이것은 가상의 위험이 아닙니다 — 국내에서 만들어진 스크립트·데이터 파일이
cp949 인 경우가 흔합니다.

방향까지 말하면: 우리 병과 **정확히 거울상**입니다. 우리는 UTF-8 파일을 cp949 로 읽어 죽었고,
그 사용자는 cp949 파일을 UTF-8 로 읽어 죽게 됩니다. 그러니 이 처방은 「무해한 설정 하나」가
아니라 **위험을 다른 사람에게 옮기는 선택**입니다. 채택한다면 그 사실을 알고 채택해야 합니다.

부수 사실 둘:
- 적용은 **새 프로세스부터**입니다. 이미 떠 있는 터미널·프로그램에는 반영되지 않습니다.
- 값 규약이 엄격합니다. `1`/`0` 만 유효하고, 그 외 비어 있지 않은 값은
  `Fatal Python error: preconfig_init_utf8_mode` 로 **파이썬 기동 자체를 죽입니다**(실측).
  따라서 설치기는 반드시 리터럴 `1` 만 씁니다.

## 4. 선택지 비교

| 안 | 하는 일 | 이득 | 대가 |
|---|---|---|---|
| **A. 아무것도 안 한다** | PR 병합·재배포를 기다린다 | 남의 기계를 안 건드린다 | 그때까지 한국어 Windows 참가자는 부활이 계속 0 |
| **B. 사용자 환경변수(이 제안)** | `PYTHONUTF8=1` User 등록 | 벤더 빌드에서도 즉시 해소·관리자 불요·제거기로 되돌릴 수 있음 | §3 부작용을 그 사용자 전체에 전가 |
| **C. 실행 지점만 좁게** | cys 를 띄우는 바로 그 자리(런처·스케줄러 항목)에서만 변수를 준다 | 부작용이 cys 프로세스 트리로 한정 | 설치기가 벤더의 스케줄러 등록 내용을 고쳐야 해 표면이 커지고, 벤더가 그 등록을 바꾸면 조용히 깨진다 |
| **D. 포크 빌드를 참가자에게 준다** | 우리 수리가 든 빌드를 배포 | 근본 수리·부작용 0 | 서명·배포·유지보수를 우리가 떠안고, 벤더 배포와 갈라진다 |

## 5. 권고

**C 를 1순위, B 를 2순위로 봅니다.** 부작용의 범위가 갈리기 때문입니다 — C 는 우리 프로세스만,
B 는 그 사람의 컴퓨터 전체입니다. 「우리 문제를 우리 경계 안에서 고친다」가 지켜지는 쪽이 C 입니다.

다만 **C 가 실제로 가능한지는 아직 실측하지 않았습니다** — 벤더 배포본의 Windows 자동가동 등록
(`W-DAEMON` · 작업 스케줄러 항목)이 환경변수를 실을 수 있는 형태인지 확인해야 합니다.
footprint.md 는 그 자국의 근거를 **「미확인」**으로 적고 있습니다. 그 한 칸을 재기 전에는 C 를
「된다」고 말할 수 없습니다. 그러니 순서는 이렇습니다:

1. `W-DAEMON` 등록의 실제 형태를 실측한다(작업 스케줄러 항목이 env 를 실을 수 있는가).
2. 실을 수 있으면 **C**.
3. 없으면 **B** — 단 §3 부작용을 참가자에게 **설치 화면에서 말하고**, footprint 에 `W-PYUTF8` 로
   등재하고, 제거기가 「우리가 만들었을 때만」 지우게 한다.
4. 어느 쪽이든 **PR 이 배포에 실리는 순간 이 처방을 걷어낸다.** 임시 처방이 영구 설정으로
   눌러앉는 것이 이 부류에서 가장 흔한 결말이므로, 걷어내는 조건을 지금 적어 둡니다:
   **참가자가 받는 배포본 버전이 이 수리를 포함한 첫 버전 이상이면 제거.**

## 6. 이 제안이 다루지 않는 것

- **맥**: 로케일이 UTF-8 이라 이 처방이 필요 없습니다. 넣지 마십시오(무의미한 자국만 늘어납니다).
- **우리 포크로 빌드된 cys**: 커밋 `07ab986` 이 이미 두 층(팩 파이썬·데몬 스폰)에서 고쳤으므로
  이 변수 없이도 동작합니다. 이 처방은 **오직 벤더 빌드용 임시 조치**입니다.
- **master 역할이 `topology.json` 에 안 남는 문제**: 인코딩과 무관한 별개 사안이며, 이 처방으로
  해소되지 않습니다.
