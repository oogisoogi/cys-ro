## §버전

- **우리 판 = 리베이스 기준이 된 벤더 태그보다 항상 patch ≥1.**
  벤더 `v0.14.30`(= `bc01f43`) 기반 → 우리 `v0.14.31`. 다음에 벤더 `v0.14.31` 을 리베이스하면 우리는 `v0.14.32`.
  근거: 같은 태그 이름이 두 판을 가리키면 영구 분기다. 실측 — upstream `v0.14.30` 은 `bc01f43` 을
  가리키는데 우리 트리는 그보다 **47커밋** 앞서 있었다.
- **실패한 태그의 번호는 재사용하지 않는다.** 태그를 옮기는 것이 곧 force 이고, 같은 번호가 두 트리를
  가리킨 이력이 남으면 나중에 「무엇이 그 번호였나」를 확정할 수 없다. 실패 태그는 **존치**한다 —
  그것이 "이 번호는 발행되지 않았다"는 기록이다.
  실적: `v0.14.31` 빌드 적색(phoenix 핀) → 수리 → `v0.14.32` 태그 → **또 적색**(내 실수: SOT 를
  0.14.31 로 둔 채 태그 번호만 올렸다 · Version SOT drift hard-gate 가 3레그 전부 차단) →
  SOT 를 0.14.33 으로 범프 → **`v0.14.33`** 으로 재발행. 소각된 번호 2개(31·32)는 존치한다.
  ⛔재발 방지 = **태그 달기 전 `sh scripts/version-check.sh <태그>` 를 로컬에서 돌린다**
  (docs/RELEASE-ROLLBACK.md §0 에 규칙으로 박음). 범프와 태그는 한 세트다.
- ⚠**브랜치명 ≠ 판번호.** 작업 브랜치 `rebase/v0.14.30` 은 「무엇을 **리베이스했나**」를 가리키는
  이름이고(= 기준이 된 벤더 태그명), 그 브랜치가 내는 우리 릴리스는 `v0.14.31`/`v0.14.32` 다.
  `release-production` 환경의 허용 ref 도 브랜치명 `rebase/v0.14.30` 그대로다(의도).
- 벤더 태그는 로컬에 **그대로 둔다**(삭제·이동 금지). 실측 유지: `v0.14.30` → `bc01f43`.
