## 1. 무엇을 바꾸나 (세 군데)
| # | 자리 | 지금 | 1.1.8 부터 |
|---|---|---|---|
| L1 | 두 설치 링크의 **시작 직후**(기존 데몬 선확인보다 앞) | 잠금 개념 없음 | `cys`(새로 받은 1.1.8 바이너리)로 전역 잠금을 잡는다. 못 잡으면(자동 갱신이 쥐고 있음) **문구 1줄로 끝** — 「자비스가 지금 새 판으로 바꾸는 중이에요. 5분 뒤 다시 붙여 넣어 주세요.」 · 3회까지 30초 간격 재시도 뒤 끝(설계 「재시도 3」). 잠금이 풀린 뒤 저널이 비종결이면 「복구 대기」 문구로 끝(복구기가 먼저 — §3-11). |
| L2 | 설치 링크가 부르는 하위 명령: 윈 NSIS(`bootstrap.ps1:3336-3343` `Start-Process $dst /S`) · rotate(`bootstrap.ps1:3460~` · `bootstrap.sh:3815~`) · init-pack | 토큰 없음 | 자기 토큰을 **위임**: NSIS = `/S /CYSTXN=<txn_id>:<epoch>`(⓪-a 가 대조 · `src-tauri/nsis-hooks.nsh`) · `cys rotate … --txn <토큰>` + env `CYS_UPDATE_TXN=<토큰>`(U2 의 `--txn` 배선 뒤). 끝나면 잠금 해제(프로세스 종료 = OS 해제). |

## 2. 왜 이 순서인가 (한 줄씩)
- L1 이 데몬 선확인보다 앞이어야 「갱신 러너가 S7(데몬 정지)~S10 사이인데 사람이 링크를 붙여 넣어 데몬을 다시 띄우는」 장면이 0 이 된다(09-19 HALT4 와 같은 계급).
- L2 의 위임이 없으면 설치 링크가 잡은 잠금을 자기 자식(NSIS ⓪-a · rotate)이 「남의 잠금」으로 보고 거부한다(자기 잠금 · 2R 신규 BLOCK 1).
- L3 은 링크 재설치로 들어온 기기가 첫 자동 갱신에서 「롤백 자산 없음(N7) = 보류」로 멈추지 않게 한다.

## 3. 시험(윈 master 실기 · W 요청문과 같은 묶음)
- 잠금 쥔 상태(가짜 러너 = `cys` 시험 명령으로 잠금만 잡고 대기)에서 링크 실행 → 문구 1줄 · 설치 폴더 파일 시각 무변화.
- 잠금 없는 정상 설치 → NSIS 인자에 `/CYSTXN=` 이 실렸는지(설치 로그 `cys: delegated by the auto-update runner` 줄) · exit 0.
- 같은 토큰을 바꿔 넣은 NSIS 직접 실행(잠금 쥔 채) → exit 6 · 무접촉.
- L3 보존 폴더의 두 파일 sha256 = 보관소 본문 행.

## 4. 맥
- 맥 설치 링크(`bootstrap.sh`)는 L1·L2 만(설치 페이로드 = 앱 번들 · 롤백 = 교환 뒤 옛 번들 — §3-5 표 첫 행 · 보존 폴더 불요).
- 맥 쪽 본문 보존(`~/.cys/update/releases/<seq>/`)은 러너가 성공 갱신 때 한다(§6-3) — 설치 링크 몫 아님.
