**① MINOR-1 이 닫혔는가 (손실 1줄이 최소인가)**
닫히지 않음 (MAJOR). `row === v.rows - 1`일 때 뒤 `\r\n`을 빼서 2줄 손실을 1줄로 줄였으나, 1줄 손실이 항상 '최소'는 아님. 마지막 행이 비어 있다면(예: 커서가 마지막 행에 있으나 내용은 없는 경우) 배너 자리를 만들기 위한 스크롤 자체가 필요 없음. 빈 자리가 있는데도 앞 `\r\n`이 무조건 스크롤을 유발하여 상단 1줄을 불필요하게 영구히 잃음.

**② 이 diff 가 새 결함을 만드는가**
- **대체 화면 마지막 행이 빈 경우 (MAJOR):** `bannerRow`가 `v.rows - 2`를 반환하면(마지막 줄이 비어 있음), `row === v.rows - 1` 조건이 거짓이 되어 기존 `EXITED_BANNER`가 선택됨. CUP로 `v.rows - 1` 이동 → 앞 `\r\n`으로 마지막 행 도달 → 배너 출력 → 커서가 마지막 행인 상태에서 **뒤 `\r\n`이 실행되며 불필요한 1번 스크롤이 발생해 맨 윗줄이 영구 소실됨.**
  - *재현 조건:* 대체 화면에서 커서가 `v.rows - 2` 이하에 있고 마지막 행이 완전히 비어 있을 때 종료.
- **판독 실패 강등 경로 (MAJOR):** `seq`의 초기값이 양옆 `\r\n`을 포함한 `EXITED_BANNER`임. `try` 블록 내에서 `buf.type`이나 `buf.getLine` 판독 예외가 터지면, 대체 화면 여부와 무관하게 초기화된 `seq`가 그대로 출력됨. 대체 화면 마지막 행에서 강등될 경우 여전히 앞뒤 `\r\n`으로 인해 2줄을 잃는 MINOR-1 결함이 방어 없이 발현됨.
  - *재현 조건:* 대체 화면 마지막 행에 커서가 있을 때, `term.buffer.active` 접근 등에서 고의로 예외를 발생시킴.
- **`buf.type` 값이 "normal"/"alternate" 외인 경우 (NIT):** 알 수 없는 타입이거나 `undefined`일 때 `v.alt`가 거짓으로 평가되어 주 화면(스크롤백 있음)처럼 취급됨. 해당 버퍼가 실제론 스크롤백이 없는 상태라면 불필요한 스크롤 손실 방어 로직을 타지 못함.
  - *재현 조건:* `buf.type`이 `undefined`이거나 서드파티 확장에 의해 다른 문자열이 주입된 상태에서 종료.

**③ 너의 1R 이 MINOR-1 을 놓친 이유가 다른 누락을 시사하는가**
1R은 `\r\n`과 CUP(커서 위치 지정) 조합이 터미널 화면 하단 경계에서 유발하는 '동적 상태 변화(스크롤 및 스크롤백 소멸)'를 머릿속으로 시뮬레이션하지 않고 정적 텍스트 단위로만 판단했음. 이는 터미널 경계 조건(Boundary Condition), 주/대체 화면 간의 속성(State) 차이, 예외 발생(Fallback) 시의 제어 흐름 등 상태 의존적인 엣지 케이스(Stateful edge cases) 검증이 전반적으로 누락되었음을 강하게 시사함.
